# 观测配置的证据准入与撤销

上一轮已发现粗分辨率预算被验证集否定。本轮将这一发现接入执行层：**有历史反证的配置不能继续被请求；全部配置失效时，不启动采集。** 同时使用新位置与方块朝向验证冻结后的选择，保留了可用性明显下降的负结果。

## 接口与规则

`admit_profiles(budgets, calibration_ids, cases)` 直接读取预算和逐帧观测。每例包含唯一 ID 与非空样本序列，每帧包含真值及每个配置的 primary/secondary 位置。估计和验证 ID 必须不重合；验证 ID 不能重复。身份分离依赖调用方正确命名，不是对数据来源的认证。

- 任一路有效位置超过任一轴预算（比较容差 1e−12 m），该配置被排除；另一视角缺失也不能掩盖已观察到的超界。
- 每个时刻均有完整两路观测才算一个完整场景。要求至少 8 个完整场景且比例不低于 2/3。重复帧不增加场景数。
- 缺失计入覆盖率，非有限位置、缺项及非法预算直接拒绝输入；不把缺失当作零误差。
- 返回不可变配置元组、独立审计快照和输入摘要 SHA256。`certified=false` 表示这是有限证据上的准入，并非统计置信度或误差上界证明。

`QualifiedViewConfirmation(start_time, admission)` 只将准入配置传给既有主动选择器。初始配置已被排除时，从合格集合中选择预算盒对角线最小的配置；原先的缺失回退也无法访问被排除的配置。空集合直接返回 `unconfirmed / no_qualified_profiles`，不调用采集器。存在合格配置时，仍遵守完整稳定窗口、原始期限与停止规则。

```python
admission = admit_profiles(frozen_budgets, calibration_ids, validation_cases)
check = QualifiedViewConfirmation(start_time, admission)
status = check.step(timestamp, locate_pair)
```

新证据用于计算**下一次执行**的准入快照，不回头修改本轮使用的预算或成绩。系统没有运行时真值，因此不能在普通相机执行过程中自动判断误差超界；必须依赖外部评估提供新的验证证据。旧的执行器继续使用已绑定快照，调用方应在下一次执行使用更新后的结果。

## 冻结旧证据后的新场景

读取上一轮 `rendered-precision-v3/report.json` 原始逐帧记录，校验提交摘要中的文件 SHA256，不信任原报告内的汇总计数。用原预算和 12 个旧验证场景计算准入：

| 配置 | 完整场景 | 超预算有效观测 | 准入 |
| --- | ---: | ---: | --- |
| 320×240 | 8/12 | 112 | 排除：预算反证 |
| 640×480 | 9/12 | 0 | 本次准入 |

规则基于已知历史问题制定，不把旧验证集再次称为盲测。随后在预先写入脚本的 12 个新位置上渲染，部分方块增加 ±0.15 rad（约 8.6°）偏航；位置均与之前估计、验证位置不同。每例 16 个时刻、5 Hz，比较沿用全部配置的旧方案与仅准入配置的方案。

两种配置在同一物理状态下采集，再分别供各策略读取所请求的当前配置。记录并校验采集不改变关节状态。报告中的请求次数是策略接口次数，不是渲染次数；实验为公平对照仍会渲染被排除的配置，仅用于对照及事后误差评估。

| 策略 | 确认数 / 12 | 错误确认 | 请求已排除配置 |
| --- | ---: | ---: | ---: |
| 原方案，保留全部配置 | 6 | 0 | 87 次 |
| 证据准入方案 | 2 | 0 | 0 次 |

这是可靠性约束的代价，不是成功率提升。12 个场景有 8 个真实位于保守确认区域内，4 个在外；确认判定仍以保守区域为准，不等同于物体掉落或完整抓放任务成功。

新场景还否定了“高分辨率足以替代粗配置”的可用性假设：

| 配置 | 新场景完整对覆盖 | 新场景超预算观测 | 合并旧/新证据后的结论 |
| --- | ---: | ---: | --- |
| 320×240 | 9/12 | 96 | 仍有反证；累计 208 次超界，排除 |
| 640×480 | 3/12 | 0 | 合并完整覆盖 12/24，低于 2/3，排除 |

合并证据后的合格集合为空。额外执行探针用该集合创建执行器，确认返回 `no_qualified_profiles` 且采集回调次数为 0。没有通过放宽预算、降低覆盖率门槛或回填缺失数据修饰结果。

## 复现与边界

```sh
make profile-admission-test
make profile-admission-evaluate PROFILE_ADMISSION_OUTPUT=outputs/evaluations/profile-admission-new
```

渲染实验需要上一轮本地原始证据 `outputs/evaluations/rendered-precision-v3/report.json`，该大文件未进入 Git；摘要中保留 SHA256，缺失或校验不符会停止。直接拉取代码不等于获得原始证据。新输出目录独占创建，运行时逐例写入阶段状态；异常保留失败记录。

[提交的实验摘要](evaluations/profile-admission-v1.json)包括旧证据哈希、源码哈希、两次准入审计、逐例状态和请求数、空集合执行探针及本地完整报告路径/哈希。完整报告还保存每帧校正结果、真值和策略日志；原始 RGB-D 图像未保存。

新增 12 项测试覆盖反证排除、重复帧计数、身份交叉、单侧有效反证、缺项和非有限值、禁止请求被排除配置、空集合、后续证据撤销、快照隔离及停止。连同已有相关回归，共 167 项通过，改动 Python 文件 Ruff 检查通过。

本轮没有训练、真机操作或默认执行入口修改。样本是有限且相关的 MuJoCo 稳定场景；不同位置仍共享同一环境与参考布局。驱动继续报告 `ARB_clip_control unavailable`，深度精度受限。下一步的实际瓶颈是高分辨率参考点缺失及粗分辨率误差，而不是继续叠加选择规则；需诊断观测链路并用新的冻结后验证证明改进。
