# 固定分母的独立曝光窗口对照

2026-11-17。本轮补上上一轮提前失败导致的样本数量不一致问题：每组预先安排 36 个独立曝光窗口，A/B/B/A 四组，两种策略各 72 个窗口。已完成的读取错误保留在分母内，然后探测下一个独立窗口；不会把它作为失败确认任务的重试或继续成功。

每个窗口使用相同 20 ms 预约提前量、2 ms 最晚曝光窗口；采用单槽位 supervised 后端、实际线程 CPU/monotonic 时钟和合成双视角读取器。进程预热后开始窗口，单次最多等 200 ms。若提交被拒绝或请求无响应，则停止继续提交，所有剩余计划项记为 not_attempted，不隐去样本。

指标按请求编号核对唯一性。只有全部计划请求都有完成结果和等待遥测，才发布 mean_wait_cpu_s；缺测时输出 null。失败窗口的 CPU 开销也纳入平均。该工具的成功退出表示测量完整和资源回收完成，不意味着所有曝光都成功。

## 本轮实测

```sh
make fixed-wait-probe-check FIXED_WAIT_PROBE_OUTPUT=outputs/evaluations/fixed-wait-probe-new
make fixed-wait-probe-test
```

| 顺序 | 策略 | 成功/计划 | 平均等待线程 CPU | 最大目标迟到 |
| --- | --- | --- | --- | --- |
| A1 | 休眠 | 36/36 | 0.125 ms | 0.462 ms |
| B1 | 最后 1.5 ms 自旋 | 36/36 | 1.387 ms | 0.190 ms |
| B2 | 最后 1.5 ms 自旋 | 36/36 | 1.402 ms | 0.036 ms |
| A2 | 休眠 | 36/36 | 0.160 ms | 0.491 ms |

两种策略都完成 72/72；休眠平均等待 CPU 约 0.143 ms/窗口，自旋约 1.394 ms/窗口，约 9.8 倍。自旋在本轮的最大目标迟到较小，但两种方案均已满足 2 ms 窗口，没有观测到成功率提升，因此仍保持默认关闭。

所有 144 个窗口都有结果与等待指标，所有监督和读取进程均确认退出。[实验摘要](evaluations/fixed-wait-probe-v1.json)保存源码哈希、原始逐窗口报告位置/哈希和每组统计。新增 4 项测试覆盖错误保留分母、缺测不发布均值、重复/缺失结果拒绝、错误指标关联拒绝；原等待遥测 3 项和预约读取器 11 项回归通过，共 18 项相关测试。Ruff 检查通过。

## 与完整恢复实验的关系

本轮隔离了曝光等待策略，不运行 31+5 帧的任务确认，也不经历初始化故障恢复。它修正的是成本比较中的样本截断问题，并没有证明完整任务恢复成功率改善。上一轮完整恢复的失败记录不被本轮 144 个独立窗口替代。

顺序做了 A/B/B/A 交错，但仍只有单轮有限样本、没有控制系统负载；最大迟到值不是总体尾延迟估计。thread_time 只包含等待线程，不是进程树 CPU 或功耗。读取器仍是合成数据，未进行实机或硬实时验证。下一步应在明确负载条件和多轮数据上检验是否值得用 CPU 换迟到余量，而不是默认推广自旋。
