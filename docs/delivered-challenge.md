# 双时钟复核：让拍摄证据服从返回期限

本轮将上一轮的曝光时间复核接入明确的结果返回时间边界，新增 `DeliveredChallenge`，并回放先前保存的双视角检测，注入延迟、丢帧、乱序及元数据故障。最关键的发现是：**当前最快 2 秒候选加 1 秒复核用满了全部 3 秒预算，没有最后一帧处理与传输延迟的余量。** 这限制了上一轮结果的实际可用性。

## 新接口与约束

```python
check = DeliveredChallenge(start_time, clock_map, session_id,
                           position_error_m=frozen_budget)
check.deliver(task_now, host_now, primary_stamped, secondary_stamped,
              session_id=current_session)
# 没有结果返回时仍需由调用者推进期限：
check.tick(task_now)
```

复用既有 `ExposureClockMap` 和 `StampedPosition`。两路必须各自携带拍摄时间，并映射到同一任务时刻；当前要求共享曝光时刻（浮点比较容差 1 ns），不支持未同步的双相机。不能把不同曝光的两帧改写成相同时间戳来绕过校验。

空间和运动证据按映射后的拍摄时间送入原 `ConfirmationChallenge`，是否超过最初 3 秒期限则按返回时的任务时间判断。过旧、未来帧、时钟映射漂移、重复/乱序曝光、未按请求时刻采集、不同步双视角、会话变更或缺少带时间戳的检测均拒绝，拒绝为终态。原模块仍负责位置和高频窗口校验。

无帧时调用 `tick` 可在期限结束关闭等待，避免最后一帧永久丢失后一直 pending。若恰在截止时刻有完整结果，调用者应先交付该结果再调用 tick；tick 已经结束的任务不会被后来的帧重新确认。任务时钟倒退或重复返回时间作为调用错误抛出，不增加证据。停止可立即取消。

适配层终态时 `next_capture_time` 为 None。快照中的 `evidence` 是原内部证据状态，可能仍 pending；外部应使用顶层 status，不能把它绕过。该模块不启动工作线程、不实现相机驱动、也不自动校准时钟；默认任务入口未更改。

## 126 组故障回放

输入是上一轮 14 条力驱动渲染案例的原始报告，先核对已提交摘要中的 SHA256。每条回放 9 种条件，共 126 组；只使用原复核方案实际收到的检测，不补造未拍摄的图像，不重新运行物理仿真。相同图像的多次故障回放不是独立物理试验。

对照为仅按曝光时间调用原模块、忽略交付元数据的用法。原模块本来就要求外部提供有效输入，因此这里验证的是新增边界的作用，不能称原算法承诺过处理延迟保障。

| 条件（每项 14 组） | 仅曝光时间对照确认 | 双时钟层确认 |
| --- | ---: | ---: |
| 按时交付 | 6 | 6 |
| 每帧延迟 20 ms | 6 | 0 |
| 仅最终帧晚 20 ms | 6 | 0 |
| 最终帧丢失 | 0 | 0 |
| 2.05 s 复核帧丢失 | 0 | 0 |
| 2.05 s 帧延后至 2.11 s 导致乱序 | 0 | 0 |
| 复核双视角曝光相差 2 ms | 6 | 0 |
| 复核中相机会话切换 | 6 | 0 |
| 复核中主机/任务时钟偏离 60 ms | 6 | 0 |

最终帧丢失时，裸曝光模块在 12 个案例中会保持 pending（包括全部 6 个原本可确认案例）；新增 watchdog 将其按时结束为 unconfirmed。时钟漂移、不同步和会话变化均按契约拒绝，不意味着回放中的物体实际放置错误。延迟后的 6 次确认也属于越过交付期限的确认，不是区域外误判。

延迟回放保持原拍摄时间，只改变结果交付事件；它没有证明串行相机能按这些时刻完成拍摄，也没有测量真实硬件延迟。20 ms 条件的所有静止/恢复确认被拒绝是重要可用性损失，不能当作单纯性能提升。

## 时间预算结论

在本轮固定采样协议下，候选最早为 2 秒，复核最少一秒，最后曝光最早为 3 秒。在保持 3 秒交付截止、这些窗口与固定采样间隔不变时，任何正的末帧延迟都会越界。该结论限于当前协议，不是所有视觉确认方法的不可能性证明。

下一阶段需要显式分配采集、处理和复核时间预算，再验证更早的候选或更短复核是否仍可靠；如果选择更长总期限，必须作为不同的延迟契约重新对照。本轮未偷偷延长期限或缩短稳定窗口，也未把零延迟仿真结果当作真实采集验证。

新增 9 项测试覆盖双时钟零延迟与偏移原点、正延迟、无帧 watchdog、重复/不同步/过旧/未来曝光、会话与漂移、任务时间顺序、停止和快照、回放迟到与丢失、构造参数及重复交付。包括相关时钟、采集、原复核及核心回归共 95 项通过，Python 文件通过 Ruff。没有新的训练、真机采集或抓放成功率结论。
