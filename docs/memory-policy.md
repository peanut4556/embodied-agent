# 带记忆的闭环学习与开发场景选模

本阶段落实 [上一轮实验文档](reactive.md) 中的两项改进：持续的执行记忆，以及按开发场景
的实际抓放结果选模型。纠正示范、视觉条件扩展尚未完成；新模型仍是独立仿真实验，
没有替换 ROS 网页中的现有反馈控制器。

后续更新：[纠正示范与质量复查](correction-data.md) 已完成首批专家接手数据。
复查确认本页的“1/3”是终点入盒率，未观察到合格抓放过程；按新的过程证据标准，
记忆模型为 0/3，原反馈控制器为 3/3。下面保留本轮原始实验口径和结果。

## 模型和因果边界

使用 64 单元、单层、单向 GRU，逐帧处理与上一轮相同的 12 维 RGB 特征、关节位置和
夹持观测，输出五个绝对关节目标。隐状态保留当前执行开始以来的历史，每次新执行创建
独立会话并清零，停止后不继续推进隐状态。输入没有阶段、时钟、重试次数或物体真值。

这次使用整段成功轨迹训练，训练时每段独立初始化隐状态，变长轨迹的尾部补齐不计入
损失。使用训练集的特征均值、尺度进行归一化；动作按执行器范围归一化。
和上一轮相比，除了加入记忆，还改成单步绝对动作目标和从第零帧开始的整段训练，
因此这是一个新的序列基线，不是严格只改变记忆长度的消融实验。

来源仍为 `outputs/datasets/reactive-development-v2`。训练 episode 为 0–4，
第 5 段失败，不参与成功动作模仿；验证 episode 为 6–8。
去除完成后的静置帧后，训练为 1,445 帧、验证为 923 帧。
观测和监督动作同帧对齐，序列不跨 episode；当前没有采集模型偏离后的纠正动作。

## 开发选模和测试隔离

先固定候选训练轮次，再对每个候选执行三个开发验证场景：x=0.312、0.372 的正常抓放，
以及 x=0.332 的外力扰动。选模依次比较：

1. 开发任务成功数，越高越好。
2. 成功数相同时，验证动作 MSE 越低越好。
3. 再相同时，选择较早的训练轮次。

`selection.json` 保存每个候选的全部物理结果，不只保留赢家。测试入口核对训练完整性、
候选集合、权重哈希、实验哈希、实际选择结果与选模规则。
如果所有开发任务失败，入口拒绝运行保留测试；选出的“最佳候选”不等于可用模型。
这一最低门槛只是避免继续评测完全失败的候选，不能解释为部署验收标准。

预留的新测试位置为 0.306、0.366、0.326、0.356，包含正常、扰动和用户停止。
它们与本轮开发位置以及上一轮已查看的四个测试位置不同。仍然是固定相机、红色积木、
固定姿态的插值场景，不是范围外泛化。物体真值只存在于仿真初始化和评测完成判断中。

## 复现

沿用 [数据集环境](datasets.md)，训练在 CPU 上运行；开发物理选模和最终评测需要
MuJoCo 图形连接。每步必须使用新的输出目录，已有结果不会覆盖。

```bash
make memory-train
make memory-select
make memory-evaluate
make memory-test
```

默认使用延长训练配置 `config/memory-extended-experiment.json`，输出到
`outputs/models/memory-bc-v2` 和 `outputs/evaluations/memory-bc-v2-development`。
`memory-evaluate` 只在开发选模达到最低门槛后运行。

复验请保持各步变量一致，例如：

```bash
make memory-train memory-select \
  MEMORY_RUN=outputs/models/memory-rerun \
  MEMORY_SELECTION=outputs/evaluations/memory-rerun-development
```

初次短训练可以用 `MEMORY_EXPERIMENT=config/memory-experiment.json`。
`MEMORY_DATASET` 指定已验证的开发数据，`BC_MODEL` 指定最终物理对比的旧反馈基线。
不要用 `make -j` 并行运行依赖前一步输出的训练、选模、评测目标。

模型文件保存特征与策略源码哈希作为来源记录；加载时校验权重、归一化和实验文件哈希。
源码哈希目前是追溯信息，不是运行时强制的版本锁。

## 本轮实际结果

先完成 600 轮短训练，预设 150、300、600 轮三个候选在开发场景中均为 0/3。
此时保留测试未执行。观察到拟合误差仍在下降后，另建有界的延长训练实验，
从相同随机种子重新训练到 3,000 轮，固定检查 1,200、2,000、3,000 轮三个候选。

| 延长训练候选 | 验证动作 MSE | 开发任务完成数 |
| --- | ---: | ---: |
| 1,200 轮 | 0.00294553 | 0/3 |
| **2,000 轮** | **0.00078881** | **1/3** |
| 3,000 轮 | 0.00069407 | 0/3 |

因此选择第 2,000 轮，**没有选择离线误差最低的第 3,000 轮**。
开发成功来自 x=0.332 场景，但外力开始时未夹住物体，该项只证明最终入盒，
不构成一次有效的滑落恢复成功。

选定后只对该版本运行预留测试，与原有反馈控制器比较：

| 新测试场景 | 带记忆模型 | 原有反馈控制器 |
| --- | --- | --- |
| 正常 x=0.306 | 稳定入盒，12.08 秒 | 稳定入盒，9.44 秒 |
| 正常 x=0.366 | 超时失败 | 稳定入盒，9.44 秒 |
| 扰动 x=0.326 | 超时失败 | 重抓恢复入盒，15.16 秒 |
| x=0.356，2 秒时停止 | 命令保持通过 | 命令保持通过 |

最终任务完成为 **1/3 对 3/3**。入盒的验收只要求物体在盒内并已松开，持续一秒，
再保持动作目标演化一秒；不能仅凭这个终点判断证明抓取过程平稳或接触质量良好。
模型在扰动测试中没有在预定时刻建立夹持，故有效滑落实验为零，不能计算有效恢复率。
两项超时任务在 24 秒预算后停止，再观察约一秒，报告总时长为 25.04 秒。

上一轮 MLP 的 0/3 使用了另一组测试位置，不能把两轮的数字当成同场景的严格提升幅度。
这里只能确认：新的带记忆模型在本轮一个未用于选模的位置实现了任务终点，整体可靠性
仍落后于旧反馈控制器。四个新测试结果现已查看，不再作为后续调参后的独立新测试集。

机器可读的全部训练、开发选模和测试结果已保存为
[memory-bc-v2.json](evaluations/memory-bc-v2.json)。本地每次运行的动画位于
`outputs/evaluations/memory-bc-v1-development/`、`memory-bc-v2-development/` 和
`memory-bc-v2-test/`。本轮共 18 次开发物理执行、8 次最终对比执行，以及
8 项新专项测试、5 项 MLP 测试、8 项时间窗口测试和 20 项核心测试，均完成；
任务失败如实列出，未把测试代码通过当作机器人任务通过。

## 下一步优先级

1. **偏离后的纠正示范**：采集学习模型实际产生的偏离状态，再由可验证的专家控制流程
   从那些状态给出纠正动作。需保留“模型产生的观测”和“专家建议动作”的时序来源，
   不能把失败动作重新标成成功示范。先在开发场景验证能否减少停滞和错误接触。
2. **细分抓取质量与失败原因**：在最终入盒外，记录接近误差、夹持建立、离桌高度、
   运输丢失和释放阶段，以区分推入盒、完整抓放和偶然落盒；这些是诊断标签，不能泄漏
   为模型在线观测。仍需独立于模型的停止与动作边界。
3. **重新冻结测试**：纠正训练和开发选模完成后，使用另一组未看过的场景评价；随后
   再扩大相机、颜色、遮挡和姿态。当前尚无证据支持替换现有 ROS 控制台策略。
