# 恢复过程数据

本阶段把实际运行的 `PhysicsWorld → PolicyMotion → FeedbackExecutor` 过程保存为
LeRobot v3 数据，包含正常任务、外力滑落后的恢复，以及无法恢复或用户停止的负样本。
没有重新训练模型，也没有扩大已有策略的工作范围；目标是建立后续连续反馈训练的数据基础。

## 采集和复验

沿用 [数据集依赖](datasets.md)，需要本地模型和 MuJoCo 图形环境。

```bash
make recovery-record RECOVERY_DATASET=outputs/datasets/recovery-new
make recovery-check RECOVERY_DATASET=outputs/datasets/recovery-new
make recovery-data-test
```

`BC_MODEL` 可指定权重目录；单独复验数据不需要权重或图形渲染，只依赖相同物理场景。
采集器在独立世界中运行，不操作正在进行的 ROS 任务，不上传到 Hugging Face。
输出目录必须不存在，失败批次不会被覆盖。`make recovery-data-test` 找不到模型时跳过
需要真实权重的集成检查，因此应核对测试输出，不能把跳过视为回放通过。

默认从 `config/slip-scenarios.json` 的已查看场景采集六段。这里的 `test` 配置键沿用
上一阶段的名称；这些场景现在属于数据整理样本，**不是下一轮训练后的独立测试集**。
首批通过验证的数据为 `outputs/datasets/recovery-v2`：

| Episode | 内容 | 帧数 | 任务结果 |
| --- | --- | --- | --- |
| 0、1 | 两个正常运输 | 各 287 | 成功 |
| 2、3 | 两个外力滑落后重抓 | 各 426 | 成功，恢复一次 |
| 4 | 落点无法可靠识别 | 191 | 停止、失败 |
| 5 | 恢复过程中用户停止 | 154 | 停止、失败 |

合计 1,771 帧、25 Hz，每段终态包含一秒继续物理演化。失败 episode 的完成标记同样为真，
但成功标记为假；“采集完毕”和“任务成功”是不同概念。程序异常、写盘错误或采集中断会
把整个批次标为 `failed`，不会伪装成机器人执行失败的有效训练样本。

## 字段和采样时序

| 字段 | 含义 |
| --- | --- |
| `observation.images.overhead` | 策略本次实际接收的 RGB，240×320×3 |
| `observation.state`、`observation.velocity` | 五个关节的位置、速度，float32 |
| `observation.holding` | 新动作计算前的双指夹持输入 |
| `action` | 本帧产生的五关节绝对位置目标，float32 |
| `replay.action` | 同一动作的 float64 原值，仅用于精确物理回放 |
| `environment.force` | 评测夹具施加的世界坐标系外力，N；不作为策略输入 |
| `phase` | 本帧决策后控制状态：运行、确认夹持、恢复、完成、停止 |
| `controller.retries`、`controller.slips` | 累计恢复与滑落次数 |
| `next.done`、`next.success` | 最后一帧的终止标记及成功标记；其他帧均为假 |

关节顺序、符号和单位沿用原示范数据。回调位于策略收到观测并生成动作之后、
物理积分之前，直接使用同一份图像和夹持输入，避免把张开夹爪后的状态误当作动作前观测。
每帧只有一次采样；采样时钟必须匹配模型的 25/50 Hz。

`recording.json` 保存初始状态和求解器初值、相机标定、物理场景、模型和控制器哈希、
外力配置、最终结果及完整控制事件。积木真值位置只出现在初始化和验收元数据中。
阶段、重试、未来结果与外力属于标注或夹具信息，均列在 `excluded_input_keys` 中，
不能作为连续策略的输入；未来训练器还须按自己的观测定义处理速度等辅助信息。

## 为什么保留两种动作精度

在一个再次夹持场景中，仅用 float32 动作回放改变了接触结果，导致夹指轨迹偏离。
LeRobot 的训练张量转换还会把声明为 float64 的数值列读成 float32。因此回放器从同一
LeRobot 数据集的 Arrow 底层读取 `replay.action`，保留完整精度；同时逐帧要求其转换为
float32 后与标准 `action` 完全一致。不是用真值位置修正回放，也不重新调用策略或 IK。

回放施加保存的动作和外力，逐帧检查图像、时间戳、episode 边界、夹持输入、关节状态与速度、
阶段、计数、动作范围、外力配置和终止标签。关节位置容差为机械臂 1e-5 rad、夹指 1e-6 m，
最终物体位置容差为 1e-4 m，并独立核对是否入盒。当前六段均匹配，机械臂最大位置差约 1.2e-7 rad，夹指约 1.9e-9 m。
这是 float64 回放的保真度证明，不代表只用 float32 执行也能保证同样的敏感接触结果。

## 防止误用

`selection.json` 仅在全部复验通过后标记 `usable: true`，成功 episode 为 0–3，失败为 4–5，
独立测试列表为空。每次复验先使旧选择失效，发现损坏后 `validation.json` 标记失败，
`recording.json` 进入 `validation_failed`。失败数据仍可用于后续停止分类或结果评估，
不能当作成功模仿目标；成功选择也只是候选数据，尚未证明适合某一种新训练器。

旧的固定轨迹回归训练入口会明确拒绝 `feedback_recovery` 数据，避免把不同长度、
包含恢复和失败的样本误当作成功专家演示。后续应新建多帧观测训练入口、扩充落点与姿态，
冻结新的场景级训练/验证/测试划分，再比较任务成功率、恢复率和误停止率。

本次验收包括 20 项核心测试、27 项物理/采样/数据入口测试，以及真实 LeRobot 读写回放
与损坏拦截集成测试。篡改成功标签、外力、动作、状态和时间戳均使数据选择失效；
恢复原始文件后重新验证可恢复有效状态。原有四项物理执行回归也通过，报告保存在
`outputs/recovery-control-regression.json`。
