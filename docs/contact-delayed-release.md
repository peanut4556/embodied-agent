# 延迟释放边沿的有限意图保留

2026-10-24。修复释放信号滞后 6、7、9 帧时的误接管。仍须显式开启 contact_consistency，默认行为保持不变。

## 原因与实现

此前 ContactWatchdog 在持物信号由 True 变 False 的当帧，用机械臂当前位置判断是否主动释放。信号滞后期间机械臂已向上撤离，即使最初在托盘上方主动张爪，随后仍被判断为 contact_lost。

现在 GuardedExecutor 在一致性监控复位前读取这一段连续矛盾已有的释放资格：首次矛盾时必须具备抬升证据且位于释放区域；连续次数必须小于已有停止门槛；信号必须刚变为 False，双指命令仍保持张开。满足这些条件时，把 contact_lost 识别为 intentional_release，不启动恢复器。

没有延长等待门槛或追加新的释放计时器。重新闭爪、最初在托盘外张爪、过高释放或未取得释放资格的接触丢失仍触发恢复；持续矛盾仍先执行原停止逻辑。生产判断不读取物体位置或验收真值。

## 冻结物理回归

[配置](../config/contact-delayed-release.json)固定当前控制器哈希、两条历史动作回放及同一个初始场景，共 26 次执行。复用原审计器，独立重算实际接触与抓放质量，并核对干预前轨迹、哈希和有限命令。

|---|---|---|
| 6 / 7 / 9 帧释放滞后 | 分别在 197 / 198 / 200 帧接管后成功 | 均成功，无接管 |
| 10 / 11 / 25 帧释放滞后 | 200 帧停止 | 仍在 200 帧停止 |

原失败来源的真实 contact_lost 仍在第 79 帧触发恢复并成功；其释放滞后注入在接管前未生效，不能当作长滞后鲁棒性收益。持续假无持物仍在第 100 帧接管。所有帧从 0 起。

新增集成测试在 25 / 50 Hz 下覆盖合格延迟释放、功能关闭、托盘外张爪、过高释放和重新闭爪。31 项接触测试、2 项轨迹计数测试和 58 项核心测试通过，共 91 项；Ruff 和 diff 检查通过。

首次沙箱执行无法创建恢复器图形上下文，其结果不作为功能证据；正式结果来自授权图形环境下的完整重跑。该环境仍报告 ARB_clip_control 深度精度限制。

## 限制

这是已见场景的动作回放与监控信号注入，未训练、未做新空间泛化或真机实验。托盘外和重新闭爪的反例本轮是集成测试，不是新增的真实物理掉落实验；原失败轨迹提供了实际接触丢失的物理回归。

主动张爪后的真正滑落与传感器延迟，在现有信号下仍可能无法区分。保留释放意图不代表任务已经成功，独立质量验收仍必要。下一步应增加释放后的物体状态确认，专门覆盖张爪后落点偏离托盘的场景。
