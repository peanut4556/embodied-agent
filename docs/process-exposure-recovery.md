# 采集进程重启后的时钟与证据恢复

2026-10-29。新增实验性 `ProcessExposureObserver`，连接 `CameraProcessSession` 与 `ExposureConfirmation`。调用方在释放发生时提供任务起点；控制层把时钟映射与具体进程会话绑定，并在重启时清除旧确认器。生产默认路径未切换到本模块。

## 恢复约束

- 相机启动后轮询至 idle，调用 `bind_mapping(session_id, mapping, task_now)`。映射必须属于当前会话，主机原点不得早于该进程启动时刻，且当前双时钟对应关系必须满足映射的误差和年龄限制。映射由调用方显式测量提供，不自动猜测设备时钟。
- 未绑定映射时可以轮询启动状态，但不会主动发出采集请求。正常状态最多保持一个待完成请求；只有完成结果才送入确认器，轮询等待不会被误当成缺失帧。
- `restart()` 先清空映射与稳定性证据，再回收并启动进程。即使回收或启动抛出异常，旧证据也不能恢复。随后必须为新会话重新绑定映射。
- `step()` 检测到外部直接更换会话，或采集进程超时、退出、关闭、清理失败，也会清除确认器。调用方应通过本控制层管理重启；若绕过它并留下待消费请求，应再次重启到 idle 再绑定。
- 缺失帧或被拒绝的曝光时间打断稳定性连续区间。重启前后各不足 1 秒的片段不能合并为一次稳定成功。
- 任务起点保持不变。达到原始 3 秒期限即返回 unconfirmed，不再轮询或发出请求；该入口采用保守的到期即终止规则，不消费恰好到期的结果。重启和绑定映射都不能增加预算。
- `stop=True` 优先于时间校验，立即锁定 cancelled，清空证据并停止消费、发请求。终态不允许重启或绑定；新的释放任务需新建控制器。

## 调用与资源归属

```python
session = CameraProcessSession(CameraFactory)
observer = ProcessExposureObserver(session, release_task_time)
try:
    # 启动期间反复 step(task_now)，直至 session.status == "idle"。
    # 从当前会话取得新的主机/任务时钟配对，再显式绑定。
    observer.bind_mapping(session.session, measured_mapping, task_now)
    # 此后用严格递增的任务时间反复 observer.step(task_now)。
    # 恢复由生命周期管理侧执行 observer.restart()，再等待 idle、重新配对。
finally:
    observer.close()
```

`step` 的停止和到期分支不做进程 join，避免把回收等待加入观测轮询。调用方必须在生命周期管理侧调用 `close()`（包括确认成功、停止和到期），才能实际结束仍存活的相机进程；`close/restart` 不应进入伺服循环。实例只支持单一拥有者线程，不能并发调用。任务时间不得因相机重连而归零。

`result()` 返回状态、原因、会话、原始截止时间及映射绑定情况；`rows` 保存映射、失效事件和逐帧判断，供诊断使用。这里的视觉确认仍不替代机械任务成功判定。

## 验证

复现新增测试：`make process-exposure-test`。

8 项测试覆盖：重启清除连续证据并重新累计成功；原始期限不延长且到期不消费；外部会话变更隔离；重启失败及采集超时；停止锁定和显式关闭；缺失/旧帧打断连续性；漂移映射、未来原点与任务时间回退拒绝；真实 spawn 子进程重启、重新绑定、重新采集和最终回收。

本轮共 153 项通过：58 核心、31 接触、22 释放、13 线程采集、14 曝光、7 采集进程、8 恢复控制；Ruff 检查通过。

稳定性和任务期限使用确定性会话桩验证；实际子进程测试验证 IPC 与恢复接线，不以调度延迟作为稳定性指标。未连接真实设备，未运行新物理抓放实验，也未验证设备固件复位或自动时钟校准。

下一步可扩展恢复决策：在固定预算内限制重启次数，并给出可追踪的故障原因与恢复结果；当前重启仍由调用方显式决定。

后续已增加[有限次数的相机故障恢复策略](bounded-camera-recovery.md)，限制重启次数、检查剩余预算并记录逐次恢复结果，仍由生命周期管理侧显式调度。
