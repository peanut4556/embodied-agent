# Embodied Agent 项目全景与面试讲述

整理日期：2026-11-07；采集时序进展补充于 2026-11-09。基于仓库实现、README、全部顶层实验文档和已有评测记录。历史实验数字不是本轮重新执行的结果；不同实验的数据集、策略和成功判据不能混算。本文末尾提供完整文档索引，查阅阶段性文档时应结合其后续实验。

## 项目一句话

一个以桌面机械臂抓放为场景的具身智能开发原型：贯通自然语言规划、学习策略、ROS 2、MuJoCo、RGB-D 感知与网页交互，并围绕失败恢复、观测可信度和实验可复现性建立验证体系。

项目价值不只是让机器人动起来，而是区分“命令执行了”“任务真正完成了”“有充分证据确认完成了”，并把失败、未知、取消和超时做成可解释的状态。

## 可以直接讲的两分钟版本

> 我做的是一个面向桌面机械臂抓放的具身智能原型。任务从中文指令开始，通过本地 Qwen 和 RAI 生成结构化计划，再经过动作白名单和接口校验，经 ROS 2 驱动 MuJoCo 机械臂。底层既有规则专家，也有从 LeRobot 格式示范数据训练的学习策略，网页可以看到执行进度、暂停、停止以及失败原因。
>
> 我把工作分成三条主线。第一条是工程闭环：解决规划器和策略的依赖冲突、跨进程通信、取消和资源回收，让整条链路能运行、能停止、能回放。第二条是学习与恢复：做过首帧条件模仿学习、连续反馈 MLP、GRU、纠正示范和蒸馏实验，并用严格抓放质量判据评估。模型单独的泛化仍然有限，所以我增加接触监控和一次 RGB-D 专家恢复。在一个冻结的 16 场景网格上，原恢复器完成 2 个，新恢复器完成 14 个；这是混合系统的成绩，不是神经网络自身能力的提升。
>
> 第三条是结果可信度：我发现物体看起来在盒子里、两个视角一致，甚至拟合残差很小，都不一定足以证明结果可靠。因此又做了参考点校正、误差预算、独立检查点、曝光时间检查和高频复核。最近还发现 2 秒候选加 1 秒复核占满了三秒期限，真实处理延迟没有余量，于是把采集期限和交付预算显式拆开。
>
> 当前最完整的是可复现的仿真与验证原型，没有真机部署，也没有训练通用 VLA。我的核心收获是把规划、控制、学习、感知和系统生命周期的问题拆开验证，避免把单个成功演示或漂亮的离线误差当成可靠的机器人能力。

面试时不必一次背完全部实验。先讲这条主线，追问算法时展开学习和标定，追问工程时展开进程、取消、时钟和审计。

## 架构怎么讲

```text
中文任务 → 规则 / RAI + 本地 Qwen → 结构化任务计划
       → 安全校验与执行计划编译 → 学习技能 / 规则专家
       → ROS 2 → 二维仿真或 MuJoCo 接触动力学
       ← RGB-D、关节、接触、执行状态 ←
       → 网页反馈、失败恢复、独立视觉确认与日志审计
```

接口把语义任务与底层动作隔开。`pick(red_block)` 是高层语义，关节位置序列是低层动作；二者需要明确转换，不能直接把大模型输出当控制指令。抓取与放置也可编译成一个学习技能，但保留原始计划用于解释。

依赖隔离是一个实际工程问题：仓库验证环境中 RAI Core 与 LeRobot 的 NumPy 主版本需求不同，因此采用 `.venv-rai` 与 `.venv`，用 JSON/ROS 消息跨边界通信，不共享 Python 对象。ROS 2 在 Docker/Jazzy 环境运行，使 macOS 开发不依赖本机 ROS 安装。版本表是项目历史验证环境，不代表最新版。

停止不仅是更新网页文字：还需要取消规划工作进程、阻止迟到计划和后续动作、回收资源、锁定任务终态。项目验证过正常子进程、错误输出、运行中取消、忽略终止信号后的强制结束及超时；不能据此承诺远端 Ollama 内部推理必然立即停止。

控制台还区分“任务取消”和“执行端停止已确认”：网络故障时允许停止未确认及重试，迟到回复绑定任务编号，不能污染新任务。已用 HTTP 503 和不返回内容的本地代理做过 ROS/MuJoCo 链路故障注入；停止与状态查询使用独立超时，不能把 socket 超时误称严格总墙钟期限。

历史记录支持最近 20 个已结束任务、筛选搜索、单条/批量 JSON 导出和汇总。后续已从会话内存升级到本地版本化 JSON 持久化，采用临时文件、fsync 和原子替换；损坏文件保留并禁止覆盖，启动只恢复记录，不重新执行任务。它不是多进程数据库或在途任务断点恢复。

参考：[架构](architecture.md)、[仿真与交互](simulation.md)、[物理模式](physics.md)。

## 数据与学习这条线完成了什么

1. 建立 RGB 图像、五关节状态与绝对动作目标的数据结构，采集 LeRobot v3 演示，并做读回与物理回放。
2. 首帧条件基线用红色区域视觉特征预测整段动作；19 个位置、4,959 帧，按位置划分训练/验证/测试。三个范围内插值测试中学习策略 3/3、平均动作 2/3。它是轻量开环回归，不是 ACT、VLA 或端到端视觉闭环。
3. 外层视觉与夹持反馈处理目标位移、失败和滑落，接入 ROS/网页。模型本身未因此变成持续反馈神经网络。
4. 进一步训练连续反馈 MLP、GRU，加入纠正示范、提前接管、损失屏蔽、关节扰动增强、多种子、局部状态目标和多步目标等研究分支。
5. 学习效果没有被美化：MLP 新测试 0/3；GRU 一度有 1/3 入盒，严格抓放质量复核为 0/3；纠正微调和多种子实验仍未获得稳定改善。离线动作误差下降也未必提升任务成功率。
6. 通过动作限速对照、视觉/关节输入替换、逐关节扰动、同状态目标和自主轨迹首次偏离分析，逐步定位闭环分布偏移、腕关节输入敏感性及接触时序问题，而不是把失败简单归因于模型规模。

面试重点：我区分了离线拟合误差、状态偏差、稳定抓取、持续抬升、主动释放和最终稳定入盒，不用低 MSE 或一次落盒替代完整任务评估。

参考：[数据](datasets.md)、[模仿学习](imitation.md)、[连续反馈](reactive.md)、[记忆模型](memory-policy.md)、[纠正微调](correction-finetune.md)、[多种子](joint-seeds.md)、[状态蒸馏](state-distillation.md)。

## 失败恢复怎么讲成一个完整案例

**问题：** 只监测“接触丢失”必须先发生接触，对从头到尾抓不到的失败没有覆盖。

**改动：** 新增首次稳定抓持超时，触发后停止学习器，交给一次 RGB-D 专家恢复。仍保留总任务期限、人工停止、专家姿态拒绝和严格质量评分。

**验证：** 固定模型、参数和新位置/视觉网格，对三组执行做初始状态、图像及接管前轨迹配对。在 16 个场景中，纯策略 0/16、旧恢复器 2/16、新恢复器 14/16；全部新成功依赖专家接管。

**副作用：** 超时可能误接管本来能成功但动作较慢的策略。后来增加有界下降宽限，在六个成功正对照中，不必要接管从 5 降到 1，已见网格保持 14/16。

**正确结论：** 改善的是混合系统对特定失败模式的覆盖；不是模型自身泛化到 87.5%，也不是任意环境的真实成功率。

还完成了稳定接触判据、平面旋转尺寸检查、倾斜状态拒绝、主动释放延迟处理，以及假丢失/假持物信号注入。原 5/6 的第六例通过更早接管另行恢复，不能把新时间点实验改写成旧六例 6/6。

参考：[泛化网格](policy-generalization.md)、[首次抓持恢复](acquisition-recovery.md)、[下降宽限](descent-recovery.md)、[接触故障](contact-faults.md)。

## 感知、几何和统计验证怎么讲

从 RGB-D 定位扩展到“何时可以信任位置”：

- 分割边缘过滤、深度连续性与同面点分组，审计倾斜面、候选法向、已知尺寸一致性及空间留出验证。
- 已知尺寸与误差预算下的保守包络、方向约束、夹爪路点扫掠和有界细分；区分观测可见表面和物体完整外形，区分保守重叠和实际碰撞。
- 多参考面外参/深度偏差拟合，分析可观测性、共同偏差、空间窄区域和参考遮挡；低残差并不证明参数正确。
- 用独立重复曝光估计像素噪声与曝光共享偏差，做独立批次、估计不确定性、方差界与尾概率消融。单批估计约 0.998/0.971 mm，接近生成值 1 mm，这是合成实验，不是真实传感器精度。
- 对数值拟合停滞作诊断；候选驻点规则在新批次把窄区域未知从 1429 降到 16，但保留秩不足与越界未知，区分数值可用和模型可信。
- 固定参考点平移校正进一步扩展到刚体校正：三点拟合，额外离面检查点独立验收，并限制目标外推距离；双视角一致仍不能排除共享偏差。
- 以完整误差框落在确认区域内作为条件，而非只看点估计。预算被新证据否定时撤销配置准入；全部配置失效则不启动采集。
- 通过连通区域修复小亮点导致检查点拒绝；将颜色身份与深度覆盖分离，避免深度空洞掩盖第二个同色目标。
- 建立外部观测严格导入和联合报告，分别处理身份/时钟/坐标配对、证据完整性、拟合和独立外部误差检查。当前无真实外部批次，不做自动校正认证。

这个方向适合突出：我把检测、估计、数值停止、统计可靠性和执行许可分开，任何一层通过都不自动代表下一层可靠。

## 观测生命周期和最近的进展

释放事件与视觉完成分开；确认失败可进行有上限复查，成功后仍可独立监测，区域外告警再进入有限复查。后续告警不会抹掉原始确认记录。覆盖率通过独立区间并集审计，避免把“没有新帧所以没有告警”误读为安全。

相机链路从线程异步采集发展到独立进程：单个在途请求、超时隔离、旧帧拒绝、取消、卡死/崩溃回收、有限重启、会话和时钟绑定、证据重置及所有权交接。真实子进程测试验证的是生命周期，不等于真实相机精度验证。

最近的运动实验用真实仿真外力驱动方块，以 500 Hz 物理步记录真值。发现 5 Hz 图像可能漏掉约 2.07 mm 的帧间运动；长窗口不能补回没拍到的信息。于是做 20 Hz、固定非等间隔、随机计划及候选后复核对照，量化延迟、拒绝与采集代价。

候选后复核在一组 14 场景实例中阻止两次低频周期运动确认，保留六次静止/恢复确认，实际采集 306 次，持续 20 Hz 为 798 次；两种判定规则不同，不能宣称等效可靠性。

进一步加入曝光/交付双时钟发现三秒协议没有处理余量。本轮新增显式 100 ms 交付预算：采集仍在三秒内完成，总交付期限变为 3.1 秒。308 组固定图像回放中，20/80/100 ms 延迟下原六次确认恢复，120 ms 仍拒绝，故障检查继续有效。它是交付预算机制，不是已完成真实 20 Hz 相机流水线。

2026-11-09 补充：新增单请求在途采集控制器，并在请求发出时重新渲染 RGB-D。30 条虚拟服务时间运行显示，20/50 ms 串行处理可完成复核，80/100 ms 无法产生所需曝光节奏，因间隔超限拒绝。这进一步区分“已有图像可以在期限内返回”和“在线能否按时拍到图像”。驱动取消仍由调用方执行，虚拟服务时间不等于真实相机吞吐测试。详见[因果时序验证](serial-challenge.md)。

| 数字 | 可以说什么 | 必须连带说的条件 |

## 常见追问的回答要点

**为什么没有直接训练大模型/VLA？** 当前场景、数据和算力下，先建立可重复的闭环和诊断基线。项目确实做了学习实验，但不把 LeRobot 格式支持说成 ACT/VLA 已部署。下一步是否换模型应由失败分布和数据覆盖决定。

**为什么离线误差变小，任务仍然失败？** 自主闭环进入训练分布外状态，小动作误差会累积；抓持接触与释放是离散事件，对时序敏感。项目做了输入替换、敏感性、同状态目标、纠正微调和自主轨迹对照，验证不能只依赖离线损失选模。

**专家恢复是不是取巧？** 它是明确标注的混合控制设计。三组配对分别报告纯策略、旧恢复、新恢复，并记录何时接管、接管前是否一致、原本成功是否受损；不把专家动作计成策略泛化。

**SafetyGate 保证安全吗？** 它负责格式、动作白名单和计划步数等边界。真机还需要独立急停、碰撞检测、关节/速度/力矩限制、通信 watchdog 等；项目没有声称获得机器人安全认证。

**双视角一致为什么还会错？** 两路可能共享标定偏差、参考表错误或目标局部偏差。增加独立参考/检查点和显式误差预算可以暴露部分问题，但独立性、预算正确性和模型匹配仍需证据。

**怎么避免数据泄漏和自我证明？** 按场景划分，训练只访问训练集，用开发场景选模；真实状态只用于评分；新网格运行前冻结配置和源码哈希；已经看过的测试不能再次冒充调参后的独立测试。保留未知和失败，报告全案例分母。

**怎么证明实验能复现？** 提供 Makefile、脚本、配置、种子、模型/数据/代码哈希、原始轨迹和审计摘要。可复现不等于原始文件都在 Git：outputs 通常被忽略，重跑某些实验需要本地数据、权重、Docker、图形环境。

**最难的问题是什么？** 可以选三者之一深入：闭环学习损失与真实抓放质量脱钩；故障恢复改善与误接管之间的权衡；曝光时钟、交付时钟和采样盲区共同造成的虚假确定性。讲清一个问题的失败证据、对照、改动和局限，比罗列模块更有说服力。

**现在离真机还差什么？** 具体机械臂动作空间与驱动、相机同步及标定、真实延迟分布、硬件安全层、真实扰动数据和更大独立评估。当前缺少真实外部观测批次，不能用仿真成绩代替真机验收。
