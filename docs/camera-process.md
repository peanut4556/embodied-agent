# 相机采集进程的退出、回收与会话隔离

2026-10-29。新增实验性 CameraProcessSession，使用 spawn 独立进程创建相机对象并调用 read()。相比线程适配层，它允许生命周期管理侧回收被阻塞的采集进程，而无需等待相机回调自行返回。生产默认路径和现有观测确认器未接入该模块。

## 进程与协议

调用方提供可序列化、在模块顶层定义的相机工厂；子进程调用工厂，设备资源归子进程所有。启动完成后发送 ready，父进程才允许 request。每个会话最多一个待完成请求，结果只消费一次。

每次启动生成新的会话 UUID、通信管道和请求计数。结果同时核对会话标识及请求编号；异常初始化、进程退出、协议不匹配和超时都不能当作成功。子进程只传递三个有限坐标、采集时间和有界错误文字；父进程再次检查采集时刻位于请求开始与接收之间，拒绝旧时间戳。

相机 read() 返回 StampedPosition 或 None。曝光时间仍必须映射到同一主机单调时钟域；进程隔离不会替代设备时钟校准。

## 超时与重启

默认启动期限为 5 秒、请求期限为 250 ms。poll() 不等待设备 read 完成；超时后停止接受当前结果，也不允许在同一超时会话中继续发请求。不会自动重启设备。

显式 close() 先发送终止信号，等待一个可配置的清理间隔；仍存活则强制结束，再等待一次。默认每次等待 200 ms。只有确认旧进程已退出并完成 join 后，才关闭通信及进程句柄。若仍未回收，状态为 cleanup_failed，restart() 不创建新进程，避免积累失控实例。

restart() 先执行上述清理，再创建全新会话。旧管道内未消费的结果被丢弃，新会话不会复用它。last_exitcode 保留最近一次回收的退出码，便于区分正常退出、设备异常和信号终止。

close/restart 包含有界等待，属于生命周期管理操作，不应直接放入高频机械控制循环。它们不是相机驱动的优雅关闭协议；强制结束也不保证实际设备固件立即复位。操作系统调度与不可中断内核等待仍可能影响清理，不能把两次等待参数当作硬实时保证。

## 实际进程测试

新增 7 项测试，实际启动子进程验证：

- 新结果只消费一次，待完成请求存在时拒绝额外请求。
- 阻塞 read 超时后回收旧进程，新 PID 和新会话能返回新位置。
- 旧结果留在旧管道中时重启，新会话不会读出它；新会话的旧时间戳仍被拒绝。
- 驱动进程以退出码 7 异常结束，父进程识别并回收。
- 初始化失败及无效超时参数不会变成成功。
- 驱动进入阻塞调用并忽略终止信号后，强制回收分支完成，退出码反映强制终止。

共 145 项测试通过（58 核心、31 接触、22 释放相关、13 线程采集、14 曝光流水线、7 进程采集）；Ruff 与 diff 检查通过。测试使用相机桩，未运行新物理实验或连接真实硬件，也未测量统计延迟上界。

## 使用与后续范围

```python
session = CameraProcessSession(CameraFactory)
try:
    # 控制调用方轮询到 idle 后发出请求，再轮询消费一次结果。
    session.poll()
    if session.status == "idle":
        session.request()
finally:
    session.close()
```

复现：`make camera-process-test`。spawn 工厂不能是局部闭包，应用入口也需遵循 Python 多进程的 main 保护规则。子进程只承担采集，不能发机械臂命令或复用主进程中的渲染器。

本模块只隔离进程、通信和数据会话，尚未自动重建上层时钟映射或清除确认器的历史证据。下一步需要让观测控制层显式绑定会话标识，在设备重连时结束旧确认流程并要求新的映射，避免仅隔离数据却沿用旧证据。

后续已新增[进程重启后的时钟与证据恢复控制层](process-exposure-recovery.md)：显式绑定会话、重启清空映射与稳定性证据，并保留原任务期限。它仍是实验性入口，需要调用方提供新映射并管理最终回收。
