# 长窗口原始位置范围检查

本轮增加独立的一秒原始位置范围门槛，补充三帧去噪的短窗口运动保护。在预设动态渲染轨迹中，新方案保留全部静止和停止后确认，额外拒绝 4 个仍缓慢移动的确认；代价是确认延后 0.4–0.6 秒。额外拒绝的目标仍在区域内，不能称作纠正了错误放置判定。

## 新行为

```python
check = SettledReferenceConfirmation(start_time, position_error_m=frozen_budget)
check.step(timestamp, primary_corrected_xyz, secondary_corrected_xyz)
```

继续使用上一轮 `GuardedMedianPair`：当前原始位置先通过双视角、误差范围和运动检查，然后才进行三帧去噪。新模块另外保留最近至少一秒原始位置：两路各自的每个轴最大值与最小值之差都不得超过 1 mm。

只有长窗口合格，才把滤波输出送给最终确认器；否则提交缺失证据，中断最终稳定窗口。缺失、原始空间拒绝或采样间隔超过 0.25 秒会清空长窗口；明显原始运动重启窗口。两路分别检查，不能用主视角掩盖次视角漂移。

在 5 Hz 连续稳定输入下，一秒原始证据收集后，还需一秒最终稳定输出，最早约 2 秒确认；原始 3 秒期限不延长。时间戳错误不增加证据，停止与终态锁定沿用原有语义。默认执行入口不变。

1 mm 是观测范围门槛，不等同于零速度。单元反例显示：理想无噪声下 0.4 mm/s 的低幅漂移仍可能通过。该门槛也不能检测帧间未采样运动、共同坐标偏差，或保证确认后目标仍留在区域内；确认后的持续监测不在本轮范围内。

## 动态图像对照

这是**预设运动学位置的渲染测试**：先让方块稳定落下，再按每个时刻指定的 X 位置更新 MuJoCo 自由关节并执行前向计算。不是外力驱动的自由物理轨迹，更不是真实机器人实验。代码检查图像采集不改变预设姿态。

两种方案读取相同的 RGB-D 检测；每帧全深度图增加标准差 1 mm 的独立高斯噪声。保持已冻结的位置预算、参考检测、刚体校正及截止时间，使用两个固定新种子，每例 16 帧、5 Hz。

v1 先测静止、2 mm/s 持续漂移、6 mm/s 移动至 0.6 秒后停止，以及确认前离开区域。两种方案在这组上都拒绝漂移和离开，**未显示新增拦截收益**。保留原始 v1 报告。

随后 v2 扩展固定网格，加入 0.4、0.8、1.2、1.6 mm/s，重复原四种轨迹，算法和阈值不变。该扩展根据开发结果设计，属于诊断网格，不是独立盲测。

| 轨迹（每项 2 例） | 原三帧方案确认 | 新方案确认 | 确认时间：原→新 |
| --- | ---: | ---: | --- |
| 静止 | 2 | 2 | 1.4→2.0 s |
| 0.4 mm/s 持续移动 | 2 | 0 | 原 1.4 s，新超时 |
| 0.8 mm/s 持续移动 | 2 | 0 | 原 3.0 s，新超时 |
| 1.2 mm/s 持续移动 | 0 | 0 | 均未确认 |
| 1.6 mm/s 持续移动 | 0 | 0 | 均未确认 |
| 2.0 mm/s 持续移动 | 0 | 0 | 均未确认 |
| 移动至 0.6 s 后停止 | 2 | 2 | 2.2→2.6 s |
| 确认前离开区域 | 0 | 0 | 均未确认 |

新方案没有确认仍在移动的案例，但这只是该网格结果。噪声、像素采样和估计离散变化会放大观测范围，因此它也可能拒绝低于名义速度阈值的移动。旧方案在理想合成 2 mm/s 输入上会确认、在本次渲染上却不会，说明不能把理想轨迹单元测试的优势直接当作图像系统收益。

全部确认时的真实位置均在保守确认区域内，所以两种方案本组区域外错误确认都是 0。报告中的 `continued_drift` / `while_drifting` 专指真实速度大于 1 mm/s；它们在该网格都为 0。摘要另列 `any_nonzero_motion_confirmations`，按真实速度大于零统计，为原方案 4、新方案 0，避免把小幅运动遗漏或混作错误放置。

新增 8 项测试覆盖静止确认时刻、理想慢漂移、次视角漂移、停止后恢复、缺失与原期限、重复时间戳、低幅漂移可通过反例、停止和快照隔离。共 **200 项测试通过**，改动 Python 文件 Ruff 检查通过。

本轮没有重新评估或宣称改进动态位置误差预算，也没有证明真实停止、接触稳定或完整抓放成功率提升。图形驱动仍报告 `ARB_clip_control unavailable`。下一步应使用动力学驱动的扰动及独立运动真值，确定这种更保守的门槛是否值得增加的延迟和拒绝率。
