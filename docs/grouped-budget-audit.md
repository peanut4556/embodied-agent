# 意图清单自动分组快照

日期：2026-11-19。

本轮把同池 lookup_many 接入已有 audit_manifest 和 audit_budget_recovery.py。调用命令和清单格式不变，不需要手工从意图文件提取编号。

清单整体合同通过后，先读取并校验每份意图和可选基线，再按规范化数据库路径、池编号、检查点内容分组。相同基线即使来自不同文件也可合并；一个有基线、一个无基线或基线内容不同则分组，不自动选择较弱约束。

每组使用一个 lookup_many 查询，一次读事务生成全部结果及对应检查点；同请求编号的多个意图文件在组内去重查询，但各自保留输出行与原清单顺序。计数仍是文件条目数，不能当成唯一请求数；每组同时报告 entry_count 和 request_count。

结果新增 snapshot_groups，包含组编号、数据库、池身份、状态和查询检查点；条目引用 group_id。只有整个清单恰好一个成功查询组且没有无法确认条目时，single_database_snapshot 才为 true。不同组之间可能发生并发写入，不承诺跨组原子性。意图解析失败单独保留，数据库或基线核验失败使整个对应组无法确认，其他组继续。

原有 64 条限制、退出码 0/1/2、指定检查点缺失不降级以及不修改预算、不启动采集的约束保持。read_intent 现在复用单条和批量入口，并在读取阶段拒绝超过 256 字符的池编号或请求编号，防止非法条目污染正常查询组。

新增 4 项测试验证：同组三个文件、两个请求只调用一次批量查询并保留原顺序；不同基线保持两个组；错误组不影响正常组；内容相同的两份基线合并。与同池并发快照、意图、预算及恢复回归共 63 项测试通过，Ruff 检查通过。

```sh
make grouped-budget-audit-test
PYTHONPATH=src:. .venv/bin/python scripts/audit_budget_recovery.py --manifest /path/manifest.json
```

这是恢复审计入口的一致性集成，不是机器人性能提升。多个数据库路径即使通过硬链接指向同一文件也可能被分成不同组，报告不会强行声称全局一致。意图和基线在读取后若被外部修改，本次报告使用已读取内容；没有对输入文件提供签名或全局冻结。数据库与基线共同回滚等既有限制仍在，未新增完整采集或实机实验。
