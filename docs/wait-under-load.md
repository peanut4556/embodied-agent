# 后台 CPU 负载下的固定窗口对照

日期：2026-11-17。

本轮将固定分母曝光探针扩展到两个独立后台 CPU 进程运行的环境。增加有界负载生命周期与可核验退出记录，测量全部计划窗口；不修改生产等待默认值，也不改变 2 ms 曝光门槛。

## 实验设计

- 基线按休眠／1.5 ms 自旋／自旋／休眠运行；负载阶段顺序反转为自旋／休眠／休眠／自旋。
- 每组 36 个独立窗口，每种条件下每个策略 72 个，共 288 个；预约提前 20 ms，允许窗口 2 ms。失败后下一个窗口是新的独立探针，不是失败确认重试。
- 使用实际 OS 进程、单调时钟及独立采集监督；读取器位置数据为合成数据。等待成本使用等待段线程 CPU 时间，不是全进程 CPU 或能耗。
- 两个负载进程每个周期名义计算 15 ms、周期 20 ms。每个进程独立寿命上限 20 s；正常或异常离开上下文均请求停止、join，必要时 kill。接口限制最多 4 个进程、最长 30 s。
- 先等待负载就绪，再执行全部负载组；若负载提前到期、退出不成功、采集回收未确认或窗口缺测，则命令失败。窗口自身的读取失败仍计入完整实验结果。
- 输出目录必须不存在；冻结并复核六个相关源码摘要，完整报告与摘要分别保存。保留全部失败，不因结果不好而重跑。

## 本轮结果

| 条件 | 策略 | 交付 / 计划 | 错窗 | 平均等待线程 CPU（ms/窗口） | 最大目标迟到（ms） |
|---|---|---:|---:|---:|---:|
| 基线 | 休眠 | 69/72 | 3 | 0.1663 | 9.6941 |
| 基线 | 1.5 ms 自旋 | 72/72 | 0 | 1.3455 | 1.0492 |
| 两个 CPU 负载进程 | 休眠 | 72/72 | 0 | 0.0508 | 0.2410 |
| 两个 CPU 负载进程 | 1.5 ms 自旋 | 72/72 | 0 | 1.3768 | 0.000208 |

288/288 窗口均取得等待遥测；总交付 285/288。基线首组第 18、21 请求和末组第 23 请求以 `scheduled_capture_window_missed` 拒绝，未放宽门槛。所有采集组均确认进程回收。

两个负载进程各运行约 3.578 s，实际消耗 CPU 分别 2.638 s、2.640 s，约为各自墙钟时间的 73.7%／73.8%；均按请求停止、退出码 0。这是每个进程的 CPU 时间比值，不是整机占用率。

自旋平均等待 CPU 在基线约为休眠 8.1 倍，负载阶段约 27.1 倍。本轮观察到基线交付差异，但负载阶段无交付收益；默认继续关闭自旋。

## 结论边界

两个后台 CPU 进程不等于整机饱和，也没有证明采集进程与负载争抢同一核心：本实验不绑核。基线全部先于负载执行，条件顺序与时间混杂；组内反转策略顺序不能消除这个问题。不能说“加负载提高成功率”，不能用单轮 72 个窗口和样本最大值宣称总体尾延迟保证。极小的目标迟到仅是等待循环退出时的时钟差，不是相机曝光精度。

这是一项短时隔离调度实验，不能代替完整故障恢复任务或真实硬件验证。独立寿命上限有正常计时退出测试，本轮未注入父进程死亡或系统冻结。后续可在不同时间做预先固定数量、交错条件的重复实验，并记录机器环境，再评估是否存在稳定收益。
