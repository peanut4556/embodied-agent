# 预约式两阶段确认：从曝光槽位到完整证据链

2026-11-13。接续[提前预约曝光原型](scheduled-capture.md)，新增可选 `ReservedTwoStageController`，将预约采集接入已有真实进程运行器和“候选证据 → 新鲜见证”流程。当前验证的是合成读取器的完整视觉证据确认，不是机器人抓放任务或真实相机性能。

## 完整协议

候选阶段继续使用 31 次相位扫描计划和 2 ms 曝光窗口，但允许提前最多 20 ms 发出预约。实际请求时间与目标曝光时间分别保存。第一帧前显式预留 20 ms 准备期：时钟映射从准备期开始，证据起点设为 20 ms 后。相对于证据起点的原采集、交付期限没有变长，端到端流程则增加了这段准备时间。

预约适配器到目标时刻才调用底层读取器。控制器也独立复核两路曝光的目标窗口，不把驱动的成功返回直接当成有效证据。流水线基础类补充了计划窗口下界检查：即使调用方绕过预约读取适配器，也不能把提前曝光的帧交给候选确认。普通到点派发原本就通过请求时间下界阻止这种帧；其默认流程不变。

候选收齐且没有未返回的候选请求时，才创建原有 `FreshWitnessGate`。顶层仍为 pending，历史候选不会直接成为最终确认。此后依次预约 5 个新见证：

- 每个见证至少预留 8 ms 派发时间；目标同时不得早于上次实际曝光后 10 ms。第一个目标不得早于候选交付后 10 ms。
- 每个见证也有明确的 2 ms 目标窗口；计时基于实际曝光，而不是预约目标或结果返回时间。
- 原门槛保留：帧龄不超过 20 ms、曝光间隔 10–30 ms、五帧跨度至少 40 ms、见证总期限 100 ms，以及原有空间和运动检查。
- 请求超时仍从实际创建时计算，候选为 250 ms、见证为 30 ms，预约等待计入其中。
- 请求编号全流程单调递增，最多 36 个；候选最多两路在途、见证一次一路，无失败补拍。

停止或超时后，所有尚未完成预约保持在取消清单中，运行器终止并回收工作进程；迟到返回不能改变终态。见证阶段停止或卡住时，也不会把已完成候选升级为成功。

当前实验配置要求时钟映射 rate=1，且映射起点覆盖准备期；不支持静默换算到未经验证的时钟速率。它复用 `TwoStageCaptureRuntime` 和 `ScheduledReaderFactory`，尚未接入 `CaptureRecovery`、默认控制台路径或真实设备动作。

## 真实进程对照

同一合成固定位置读取器，正常条件与派发前 sleep 5 ms 条件，各比较到点模式和预约模式两次，第二轮交换执行顺序。执行过程中没有并行运行本项目回归测试，但没有操作系统实时优先级或负载隔离。每次都执行完整确认流程，失败即停止，不挑选通过结果。

| 条件 | 到点派发完整确认 | 预约式完整确认 |
| --- | ---: | ---: |
| 正常 | 1/2 | 2/2 |
| 派发前等待 5 ms | 0/2 | 1/2 |

通过的运行均完成 31 次候选采集和 5 次新鲜见证，共 36 次请求。预约模式在派发延迟条件下的一次完整通过，将上一轮“个别曝光窗口按时完成”的结论推进到了整条证据链。

失败仍然重要：

- 正常到点模式有一次在第 26 个请求曝光超窗。
- 5 ms 派发延迟下，到点模式两次均首帧超窗；预约模式一次在第 25 个请求因工作进程过晚唤醒而拒绝，驱动日志为 `scheduled_capture_window_missed`。
- 额外的真实进程见证运动注入运行，在候选第 29 个请求后因下一预约提交过晚而终止，**未进入见证阶段**，因此不能用这次真实进程运行宣称验证了见证运动拒绝。该拒绝路径由虚拟时钟状态机测试验证。
- 额外的预约等待期间停止运行，发出 1 个预约后取消；没有生成最终确认。

共 10 次真实进程运行全部核实工作进程退出。两个重复运行只构成机制演示，不构成稳定成功率估计。原有窄脉冲漏检、真实相机校准/驱动延迟等限制也未解决；最终状态依旧只表示近期证据通过，不保证当前或未来始终静止。

## 使用与验证

```python
backend = ProcessPairCapture(ScheduledReaderFactory(camera_factory))
try:
    if backend.wait_ready():
        origin = time.monotonic()
        controller = ReservedTwoStageController(
            0.02, ExposureClockMap(origin, 0), session_id,
            position_error_m=validated_error_budget,
        )
        runtime = TwoStageCaptureRuntime(controller, capture_backend=backend)
        while runtime.step() == "pending":
            time.sleep(0.0005)
        result = runtime.result()
finally:
    backend.cancel()
    cleanup = backend.reap(0.25)
```

