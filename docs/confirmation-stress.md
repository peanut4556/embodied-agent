# 确认策略的随机化合成故障压力测试

日期：2026-11-22。

本轮沿用上一轮三个配置，不调参、不训练。8 类场景各 20 个固定种子（22000–22019），共 160 个预生成流，三个配置分别运行同一个流，共 480 个单步 verify 任务。预先保存完整计划、配置和源码哈希，不因失败重跑。

流以 5 ms 周期生成 64 个观测槽位；每次读取开销在 1–6 ms 中按种子生成，模拟时钟加上轮询睡眠后选择当时槽位。有效类为持续正确、延迟 10–120 ms 更新、45% 概率重复最近帧的 dropout；异常类为 5 ms 短误报、5–80 ms 突发误报、旧戳、重复戳、持续错误但具有递增时间戳的正面状态。dropout 表示重复缓存，不是 observe 阻塞或缺失返回。标签是夹具预设，未传给控制器，不是物理传感器真值。

| 配置 | 异常误接受 / 100 | 有效场景漏检 / 60 |
|---|---:|---:|
| 立即确认 | 100 | 25 |
| 新鲜度确认 | 80 | 0 |
| 时间跨度确认 | 30 | 3 |

时间模式具体为：短误报、旧戳、重复戳各 0/20 误接受；较长突发 10/20，持续错误观测 20/20。有效延迟更新漏掉 3/20，持续正确与 dropout 均无漏检。三种配置对持续错误观测都 20/20 误接受，这是必须保留的反例。全部运行仅执行一次动作，没有重放。

不同配置可能在不同时间结束，读取流的前缀长度不同，但生成流相同且不随控制器结果改变。随机参数来自人工选择分布，各类别复用相同种子；种子数不能当成真实部署独立样本，也未做显著性检验。持续正确与持续错误类故意提供不可区分的正面观测，用来展示单一观测合同的信息边界。

结论：时间约束可以过滤这些短暂或旧帧反例，但更长突发仍会通过，等待时间又可能导致迟到有效状态漏检。不能仅靠增加同源样本数证明真实完成。下一步应定义独立证据来源及冲突处理合同，而非把当前零误判测试当成部署保证。

新增三项测试验证计划可复现、480 配对完整且不重执行、持续错误反例确实击穿全部模式、运行不污染计划。与既有主运行测试合计 41 项通过，Ruff 及源码/计划/报告哈希校验通过。
