# 独立稳定性判据与区域边界计时修复

2026-10-31。本轮增加独立离线判据，与在线 ReleaseConfirmation 的首次成功时间比较，发现并修复区域外时间被借入稳定窗口的问题。

## 缺陷与修复

确认器要求点位在保守确认区域内，连续至少 1 秒；相邻曝光间隔不超过 250 ms，速度严格小于 20 mm/s。

旧实现中，上一帧在区域外时 since 为 None。如果下一帧缓慢进入区域内，虽然相邻位移满足速度限制，却会把 since 设为上一帧时间。因此区域外的一段时间被计入区域内稳定时长。

可复现案例：t=0 时 z=0.032 m，恰在被排除的下边界；之后每 250 ms 一帧，z=0.033 m。旧实现 t=1.0 s 即成功，实际区域内只有 0.75 s。修复后从 t=0.25 s 的首个区域内曝光计时，到 t=1.25 s 才成功。上下高度边界及左右侧边界均复现该问题。

修复仅改变这类窗口的起点：当之前没有有效稳定起点时，即使位移足够小，也从当前区域内曝光开始。原有区域、速度、间隔、期限和时长阈值保持原值。所有使用 ReleaseConfirmation 的调用方均继承修复，包括双时钟确认器。

## 独立对照

参考判据不调用在线确认器的内部状态或辅助函数。它枚举截至当前曝光的所有连续窗口，检查窗口中每个点都在区域内、每条相邻边的间隔与速度满足条件、窗口覆盖至少 1 秒，并计算首次可确认时间。在线路径则继续使用增量状态机。

固定种子 20261031，共 413 个案例：4 个进入边界案例，3 个间隔案例（249/250/251 ms），3 个速度案例（19.9/20/20.1 mm/s），3 个时长案例（999/1000/1001 ms），400 个混合缺失帧、边界点、位置变化和不规则曝光间隔的随机序列。

| 对照 | 案例数 | 首次确认时间不一致 |
| --- | ---: | ---: |
| 修复前 | 413 | 4 |
| 修复后 | 413 | 0 |

[修复后完整判定表](evaluations/release-stability-v2.json) 保存每个案例的预期/实际首次成功时间，边界序列完整保存；随机序列按脚本中的固定种子重建，失败时也会完整写出。修复前结果来自修改前运行同一判据，四项不一致都是提前 250 ms 确认。

这是独立实现的窗口判据，但区域阈值与浮点语义仍按既定规格一致设置；它不是形式化证明，也不代表穷尽所有轨迹、相机误差或设备时钟问题。

## 重放版本迁移

新报告使用 exposure_confirmation_v2 算法标识，证据格式版本仍为 1。旧 v1 算法证据保留，离线审计返回 unavailable / superseded_confirmation_algorithm，不把旧记录按新判据静默重算为已验证。缺少原始证据的更早报告继续返回 legacy_report_without_raw_evidence。

[新版场景证据](evaluations/recovery-evidence-v2.json) 与[版本迁移检查](evaluations/recovery-replay-v2.json) 保存 8 个 v2 场景 verified、8 个 v1 场景 unavailable 的结果。两组用于格式兼容性对照，不是独立可靠性批次；历史报告不改写。

## 验证与使用

```sh
make release-stability-test
make release-stability-audit
make recovery-replay-check
```

输出路径已存在时拒绝覆盖，可用 RELEASE_STABILITY_OUTPUT 或 RECOVERY_REPLAY_OUTPUT 指定新路径。

新增 6 项测试覆盖 413 案例差分矩阵、边界进入计时、双时钟传播、缺失/间隔中断、速度与期限、v1 算法迁移。相关回归共 198 项通过（58 核心、31 接触、28 释放、13 线程采集、14 曝光、7 采集进程、8 进程恢复、39 恢复相关），Ruff 与差异检查通过。

本轮没有连接真实相机，没有新物理抓放实验或训练；结论是软件判据的边界修复及回归验证。

后续已完成[稳定证据中断与重新累计的穷举验证](stability-interruptions.md)：19,683 条离散序列与 45 条定向轨迹，覆盖区域外/缺失帧、速度突变、间隔阈值及接收期限。
