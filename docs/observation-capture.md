# 可取消、有限并发的观测采集适配层

2026-10-27。新增 ObservationCapture 与 CapturedReleaseObserver，供独立相机驱动显式接入。控制线程不直接执行阻塞采集，通过非阻塞轮询获取新结果；原同步观测路径和生产默认配置不变。

## 接口与行为

驱动提供 read(cancel_event) 回调，返回三个有限位置坐标或 None；回调应独立拥有相机资源。适配器使用单个在途守护线程，从发起请求时起计算单调墙钟年龄，默认有效期 250 ms。结果被复制后只消费一次，不缓存为后续位置；接收时已过期的结果也会丢弃，即使底层调用曾及时完成。

采集超时后返回缺失观测，仍保留原在途调用的位置，不启动额外并发调用。原调用最终返回后，其迟到结果被丢弃，下一次请求才能开始。捕获驱动异常和非法坐标，保留错误文字，并向确认器提供缺失观测；开发测试曾发现非法坐标被错误保留，现已修复并加入回归。

cancel() 永久关闭该适配器，设置驱动取消事件，不等待线程 join，也不再接受迟到结果或新请求。CapturedReleaseObserver 在 stop=True 时先取消采集，再向观测分支传播停止；正常确认结束时也关闭采集。未收到释放事件前不启动相机。

观测分支仍以 5 Hz 处理证据。每次消费后，如果仍处于待确认状态，适配器预取下一帧，避免请求和消费交替导致有效观测间隔变成 0.4 秒。250 ms 有效期仅为实验默认值，尚未根据实际相机延迟标定。

## 验证

新增 8 项测试，使用真实工作线程、事件屏障及可控时钟验证：

- 驱动仍被阻塞时，取消处理已返回，后续结果无法重新进入确认。
- 同一超时调用遭遇 100 次轮询也不启动第二个采集，恢复后丢弃迟到成功结果。
- 结果拷贝、单次消费、完成后过期、设备异常和非法坐标。
- 停止信号穿过观测包装层，不等待相机；正常预取能积累连续新证据并确认。

共 119 项测试通过：58 核心、31 接触、22 释放相关、8 采集适配。Ruff 与 diff 检查通过。本轮没有新的物理实验或真实相机接入，也没有测定取消延迟的统计上界。

## 重要边界

控制线程能够继续处理停止，并不意味着底层阻塞驱动被强制结束。不响应取消事件的驱动仍占用一个在途线程和其资源；本适配器不通过反复重启线程绕过它。真正的设备回收需要驱动取消/超时支持，或后续采用独立进程隔离。取消采集不是机械臂急停。

回调必须只负责采集，不能发出机械臂命令。不要将共享可变 MuJoCo world 或其渲染器直接传入工作线程；本轮因此没有把现有模拟定位函数简单搬到线程中。控制层的 sample/request/cancel 由同一控制线程调用。

确认器接收的是消费时刻的位置证据；适配器只提供从请求发起到消费的年龄上限，没有设备曝光时间戳。动态物体下的时间对齐和误确认风险仍需专项验证。操作系统调度或驱动持有 GIL 的行为也不受单元测试保证。

## 使用与复现

```python
capture = ObservationCapture(driver_read, timeout=0.25)
observer = CapturedReleaseObserver(capture, allow_recheck=True)
observer.step(simulation_or_task_time, release_events, stop=user_stop)
```

任务时间控制确认预算，内部单调墙钟控制采集年龄，两者分开。退出任务时调用 capture.cancel() 清除仍在途的结果资格。

```sh
make observation-capture-test
```
