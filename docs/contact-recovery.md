# 提前闭合与接触丢失附近的恢复样本

## 范围

基于上一轮首次偏离审计，固定使用 success-replay-replay/epoch-300 在训练位置
x=0.302 m 的自主轨迹。六个接管点在采集前冻结为 75、77、78、79、82、84 帧，
即 3.00、3.08、3.12、3.16、3.28、3.36 秒。没有根据采集结果追加或筛选接管时间。
每条轨迹从初始状态重新自主执行，再由原 CorrectionExpert 接管；不重置物体或关节。

六条全部归入训练分组，验证和测试分组为空。同一位置不会因接管时间不同被拆到不同分组。
本轮没有重训、评测新模型或替换控制台策略；3/6 是固定专家的恢复成功率，不是模型成功率。

## 实测结果

| 接管帧 / 秒 | 接管前状态 | 合格恢复 | 有效专家帧 | 结果说明 |
| --- | --- | --- | --- | --- |
| 75 / 3.00 | 无接触，闭合前 | 是 | 311 | 撤退、重新抓取并放置 |
| 77 / 3.08 | 无接触，即将输出闭合动作 | 是 | 311 | 接管发生在本帧模型动作之前 |
| 78 / 3.12 | 双侧接触，holding 为真 | 否 | 0 | 后续抬升中丢失接触，未完成抓放 |
| 79 / 3.16 | 首次接触中断 | 是 | 311 | 重新抓取并放置 |
| 82 / 3.28 | 再次双侧接触，holding 为真 | 否 | 0 | 后续抬升中丢失接触，未完成抓放 |
| 84 / 3.36 | 无接触，物体已明显偏移 | 否 | 0 | 专家拒绝视觉目标尺寸不一致或严重遮挡 |

共 **2024 帧原始记录、3 条合格恢复、933 帧有效专家动作监督**。
实际训练读取器仅返回 episode 0、1、3。自主执行前缀保留为循环模型历史，
但不是动作标签；失败整条轨迹及结束保持帧也不进入动作监督。

78 和 82 帧接管时，专家依据瞬时 holding 选择保持夹持撤退，随后发生抬升接触丢失。
这说明当前专家对这些接触状态的恢复能力仍不足；不能据此断言状态本身不可恢复。
这两条轨迹虽未触发专家异常 reason，仍因完整抓放质量不合格判失败，未误纳入训练。
第 84 帧失败反映的是现有感知/恢复流程限制，未将仿真物体真值作为替代策略输入。

## 数据与验证

数据路径：`outputs/datasets/corrections-contact-v1`。LeRobot 数据包含真实 RGB、关节、
夹持反馈、动作来源和强制监督 mask。保留 float64 replay.action 用于严格物理回放。
配置绑定源自主轨迹 SHA256 和采集模型权重，报告绑定数据 payload SHA256。

六条接管状态均与上一轮自主失败轨迹的相同帧 qpos、qvel、上一控制量在 1e-8 容差内一致。
每条记录的实际动作均重新物理回放，核验状态、质量判定、监督边界和结局。
三条成功轨迹还通过公开训练读取器核验：接管帧及之前的全部视觉特征、关节与夹持历史
匹配自主轨迹，接管前 mask 全为零、接管动作开始监督，失败轨迹被排除。

运行 `make contact-recovery-record` 采集、验证并生成机器报告，已有输出拒绝覆盖。
运行 `make contact-recovery-test` 检查固定模型、接管计划、分组及状态匹配。
运行 `make correction-test CORRECTION_DATASET=outputs/datasets/corrections-contact-v1`
覆盖既有质量判据、监督隔离及真实数据接管状态篡改后拒绝加载和重新验证。
上述共 13 项测试通过（含真实数据篡改回归），代码风格和差异检查通过。
机器报告见 [contact-recovery-v1.json](evaluations/contact-recovery-v1.json)。

## 下一步

先完善专家对“瞬时双侧接触但尚未稳定夹持”的恢复判定，再用相同六个接管点复查，
避免把 holding 一次为真直接等同于可保持搬运的抓取。成功后再扩充同一采集模型的
其他训练位置与独立验证位置，准备训练对照。

本次新增数据没有验证轨迹，不能直接作为现有微调入口的唯一纠正来源；该入口要求
训练/验证均有成功纠正数据，且纠正数据来自对应冻结父模型。旧父模型采集的数据
不能不经校验就与此次样本拼接。当前三条成功样本可作为下一阶段训练池的一部分，
但尚不能据此声称新模型恢复能力提高。

后续已加入[连续夹持判定](contact-stable.md)，同六个接管点合格恢复从 3/6 提高到 4/6。
