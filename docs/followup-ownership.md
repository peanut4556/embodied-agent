# 确认后监测的交接归属与异常保留

2026-11-02。本轮补齐此前依赖调用方约定的交接边界，防止重复接管和旧控制器关闭已交出的会话。

## 交接约束

ProcessPostConfirmation 构造成功后，在相机会话对象上保存本轮会话 ID 与唯一归属标记。同一会话不能同时构造第二个后续监测适配器，包含绕过 from_confirmed 的直接构造。参数校验失败不会占用归属。

from_confirmed 成功后将原控制器的 session_transferred 标为 True；同一原控制器不能再次交接。ProcessExposureObserver 与 RecoveryExposureObserver 的 close 在交接后直接返回，不关闭相机、不修改原确认结果，也不会把旧控制器的清理状态虚报为 succeeded。新的后续监测适配器负责 close 和清理结果。

旧控制器的 result 仍是原释放确认快照。对于 RecoveryExposureObserver，交接前的 cleanup 状态同样保留；它不再是当前会话的资源清理依据，应从 followup.result() 查看当前 cleanup_required 和 cleanup。

如果相机对象后来被外部重启或被新适配器接管，旧适配器在 step 前检查归属并停止轮询。它的 close 会拒绝关闭其他会话，记录清理失败并抛出错误；替换后的会话必须由新拥有者清理。已经成功关闭的适配器重复 close 不做任何操作，即使相机对象随后被用于新会话，也不会误关新进程。

这些检查仍要求单一拥有者线程，不构成跨线程互斥锁，也不能拦截调用方直接操作底层 session.close/restart。生产默认路径未改变。

## 上下文异常

如果 with 内部发生业务异常，而退出时 close 又失败，现在以 BaseExceptionGroup 同时保留两者；普通 Exception 会由 Python 表现为 ExceptionGroup。业务异常在前、清理异常在后，清理状态仍单独记录为 failed，可由调用方在适当时机重试。

仅业务失败、清理成功时，原业务异常原样传播。仅清理失败时，原清理异常传播。不把失败静默转换成成功返回。
