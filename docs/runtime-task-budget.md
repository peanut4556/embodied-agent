# 跨步骤任务时间预算

日期：2026-11-22。

AgentRuntime.run 新增可选 task_timeout_s，要求有限正数，默认 None 保持原行为。预算从初始观测和规划之前开始，覆盖规划、策略选择、动作执行及各步骤确认消耗的时间。规划结束、每步开始及动作派发前检查期限，耗尽后返回失败，不派发后续动作。

```python
result = runtime.run(instruction, task_timeout_s=10)
```

确认等待同时服从单步期限和任务剩余期限，ProcessWitness 继续接收两者较短的剩余预算。每步确认报告新增 task_remaining_s；任务期限导致确认结束时 status 为 task_timeout。规划或派发前超期通过 TaskResult.message 的 task deadline exceeded 表达，不伪造已执行步骤报告。取消、故障诊断和进程回收快照保留。

默认单步确认期限为零时仍只进行立即核验，不因设置任务预算而开启多次轮询；进程见证自身等待会受任务剩余预算约束。

新增 5 项确定性测试覆盖跨步骤预算、规划耗时、动作返回过晚、非法预算及默认兼容性。与主运行、真实见证进程及三组故障评测回归共 66 项通过。未重新生成冻结实验报告，没有实机验证。

这是软件期限管理，不是抢占式调度：同步规划、主观测、策略、execute 及 IPC 仍可能阻塞，返回后才可检查期限；进程回收还可能增加延迟。它保证检查点发现超期后不继续派发，不能保证机器人在期限内物理停止。任务预算仅在本次 run 内有效，不跨重启持久化，也尚未接入 CLI 参数。
