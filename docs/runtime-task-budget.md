# 跨步骤任务时间预算

日期：2026-11-22。

AgentRuntime.run 新增可选 task_timeout_s，要求有限正数，默认 None 保持原行为。预算从初始观测和规划之前开始，覆盖规划、策略选择、动作执行及各步骤确认消耗的时间。规划结束、每步开始及动作派发前检查期限，耗尽后返回失败，不派发后续动作。

```python
result = runtime.run(instruction, task_timeout_s=10)
```

确认等待同时服从单步期限和任务剩余期限，ProcessWitness 继续接收两者较短的剩余预算。每步确认报告新增 task_remaining_s；任务期限导致确认结束时 status 为 task_timeout。规划或派发前超期通过 TaskResult.message 的 task deadline exceeded 表达，不伪造已执行步骤报告。取消、故障诊断和进程回收快照保留。

默认单步确认期限为零时仍只进行立即核验，不因设置任务预算而开启多次轮询；进程见证自身等待会受任务剩余预算约束。

新增 5 项确定性测试覆盖跨步骤预算、规划耗时、动作返回过晚、非法预算及默认兼容性。与主运行、真实见证进程及三组故障评测回归共 66 项通过。未重新生成冻结实验报告，没有实机验证。

这是软件期限管理，不是抢占式调度：同步规划、主观测、策略、execute 及 IPC 仍可能阻塞，返回后才可检查期限；进程回收还可能增加延迟。它保证检查点发现超期后不继续派发，不能保证机器人在期限内物理停止。任务预算仅在本次 run 内有效，不跨重启持久化，CLI 接入见下节。

## 命令行与自动化接入（2026-11-24）

新增 --task-timeout，使用有限正数秒；省略时保持无任务总期限的行为。

```sh
PYTHONPATH=src .venv/bin/python -m embodied_agent "red block box" --task-timeout 5 --json
```

模块入口和安装后的 embodied-agent 控制台入口统一退出语义：成功为 0，返回失败 TaskResult 为 1，命令行参数解析错误为 2。JSON 与文本模式均遵守此规则；JSON 模式的标准输出保留一个 TaskResult 对象，日志走标准错误。未捕获的程序异常仍是异常退出，不伪装成 JSON 任务结果。自动化调用方应同时检查退出码和 JSON，不应仅凭退出码 1 推断具体失败原因。

这改变了此前失败任务也以 0 退出的行为：旧脚本若依赖该行为需调整。不是只对任务超时生效，任何返回失败 TaskResult 的情况均为 1。新参数在构造运行时前验证，非法数值不会启动任务。

新增 3 项测试覆盖两种输出模式的参数传递和失败返回、真实模块子进程的成功与规划阶段超期、零/负数/NaN/无穷/非数字参数拒绝。含原有回归共 69 项通过。超期子进程使用极小预算验证命令接线，不将其视为精确计时性能测量。

## 动作启动前的最低预算（2026-11-24）

run 新增 minimum_step_budget_s，默认 0 关闭。启用时必须同时设置 task_timeout_s，且预留值必须是有限非负数。策略选择和动作校验后、execute 之前，检查任务剩余时间是否至少达到预留值；不足则返回失败，不派发该动作。该条件每步重新检查，不会重置任务预算。显式 stop 动作不受这个新增预留检查阻止；原有取消与总期限逻辑保持不变。

```python
result = runtime.run(instruction, task_timeout_s=2, minimum_step_budget_s=0.2)
```

拒绝事件放在逐步报告列表 confirmation_reports 中，status 为 insufficient_step_budget、dispatched 为 false，并记录 task_remaining_s 与 required_step_budget_s。它是派发前事件，不是已执行动作的确认失败；completed_steps 不增加。旧读取方应按 status 区分报告类型，不能假设每项都有 reads 等确认字段。

新增 3 项测试覆盖尚未到期但不足预留、跨步重新检查、配置校验和充足预算。相关测试共 74 项通过。原 240 次实验在默认关闭检查时逐项保持不变，因运行时源码改变另存 task-budget-v2.json，不覆盖 v1；该实验仅验证默认兼容性，不评估预留阈值效果。

预留值由调用方提供，当前没有实机耗时分布支撑。该机制是动作准入条件，不是最坏执行时间证明；实际执行超出预留值仍可能发生。尚未加入按动作分别估计预算或 CLI 参数，也不承诺动作已启动后能够按期完成。
