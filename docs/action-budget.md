# 按动作校准准入预算

日期：2026-11-24。

新增 ActionBudget，按动作名读取离线“执行开始到确认结束”秒数样本。至少 20 个样本时，预算为样本最大值加 5 ms；不足或未知动作默认回退到 50 ms。样本在构造时复制计算，验证不更新估计。此处选择最大值加裕量是简单的保守基线，不是统计覆盖率保证。

```python
from embodied_agent.action_budget import ActionBudget
budgets = ActionBudget(calibration_samples)
result = runtime.run(instruction, task_timeout_s=2, action_budget=budgets)
```

运行时每步使用固定 minimum_step_budget_s 与动作预算的较大者，派发前检查。已执行步骤报告 required_step_budget_s、action_elapsed_s、budget_degraded。若完整执行确认耗时超过当前动作预算，或确认失败，该动作进入持续退化状态，后续使用“校准值与回退值的较大者”；不会自动恢复，需调用方以新校准样本明确重建。复用同一预算实例才会跨任务保留退化状态。进程异常直接抛出、进程重启持久化和统计变点检测不在本次范围内。

回退发生在观察到异常之后，不能保护首次漂移，也不能保证真实设备耗时不超过回退值。未知动作、样本不足和退化处理已有单元测试。未自动训练、未接入 CLI 或实机。

## 独立合成验证

分别为 pick/place/verify 生成 100 个校准样本，种子 51000..51099；验证为每动作 40 个新种子 61000..61039。使用执行加确认耗时的理想化模型，抓取 30–45 ms、放置 20–35 ms、核验 5–12 ms。验证剩余预算随机为 10–80 ms，标签只供评分，运行时不读取实际未来耗时。不同动作共享种子，并非独立同分布的 120 次实机试验。每个验证任务重建相同冻结预算，因此本实验评估校准效果，退化路径另外用单元测试验证。

| 方法 | 完成/120 | 误拒绝可行任务/95 | 已派发未确认动作 |
|---|---:|---:|---:|
| 固定 50 ms | 45 | 50 | 0 |
| 按动作校准 | 74 | 21 | 0 |

误拒绝减少 29 个，降幅 58%；仍有 21 个误拒绝。这个收益来自合成动作耗时差异，不可直接外推实机。当前分布有界、校准与验证同分布，没有证明对长尾或复杂漂移也有效。

输入样本与全部 240 个结果保存于 [实验 JSON](evaluations/action-budget-v1.json)。可复现命令（新路径，禁止覆盖）：

```sh
PYTHONPATH=src:. .venv/bin/python scripts/evaluate_action_budget.py --output /tmp/action-budget-new.json
```

相关测试 81 项通过，新增四项覆盖回退、持续退化、非法样本及独立验证/冻结结果。此前任务预算与固定准入实验结果仍逐项一致；历史 JSON 原样保留，回归比较排除来源哈希（它们记录历史版本，不应要求新源码等于旧源码），其余输入、结果、摘要均严格比较。这改变了此前“当前源哈希必须一致”的测试方式，未重写历史证据。

## 可选异常隔离策略（2026-11-24）

ActionBudget 新增 drift_policy="quarantine"；默认仍为 "fallback"。观察到耗时超过该动作预算或确认失败后，quarantine 将该动作标为暂停，后续运行时在派发前返回 action_budget_quarantined，报告 dispatched=false。其他动作不因这个标记而暂停，显式 stop 不受新增隔离规则阻止；已有总期限、取消和安全校验保持生效。

```python
budget = ActionBudget(calibration_samples, drift_policy="quarantine")
result = runtime.run(instruction, task_timeout_s=2, action_budget=budget)
```

必须跨任务复用该实例才能保留状态。恢复要求调用方显式提供重新校准样本并创建新实例；没有定时自动恢复或在线降低预算。API 不验证新样本是否真来自新采集，也不持久化跨进程状态，因此不能把它当作不可绕过的安全边界。已经发生的首次超时无法撤回；当前成功动作若超过估计预算，也会使后续同类动作暂停。

新增真实 run 路径测试验证：首次动作成功但耗时越界、第二次同类动作零派发、不同动作及 stop 不被该标记阻止、显式新校准后恢复。另验证非法策略拒绝。

## 单动作重新校准与恢复记录（2026-11-24）

新增 recalibrated(action, samples, batch_id=...)，返回新预算实例而不修改旧实例。仅允许处理已退化动作，样本必须满足原 minimum_samples、有限正数及计算结果有限。只更新该动作估计并清除其退化标记，其他动作的估计与隔离状态完整保留。比起重新构造整个预算，它避免恢复一个动作时无意清除其他故障状态。

```python
replacement = budget.recalibrated("verify", new_samples, batch_id="verify-session-002")
# 调用方明确选择何时采用新版本；没有自动恢复。
budget = replacement
```

新版本 revision 递增，历史记录包含动作、批次、样本数、样本 SHA-256、恢复前所需预算与新估计。recalibration_history() 返回深复制，外部修改不改变内部记录。已执行动作的报告增加 budget_revision，可对应使用的恢复版本。新的耗时越界或确认失败仍会触发退化。

批次标识在当前版本链内不可复用；非法输入会在创建新版本前拒绝，不更改原状态。旧实例仍保持隔离，恢复后调用方必须明确使用返回对象。该接口不是持久化注册表，不保证跨进程或不同分支的批次唯一性；换一个批次名并不能证明样本是真正新采集，摘要也不是真实性或独立性证明。原始样本由调用方留存，本对象只保存摘要。当前不保证并发线程修改状态时的原子切换，应在没有任务使用实例时进行替换。

新增三项测试验证指定动作恢复、其他动作继续隔离、真实 run 路径成功与版本报告、再次越界重隔离、失败输入不改状态、重复批次拒绝和审计快照隔离。相关回归 90 项通过。恢复样本是人工测试数据，未新增实机或独立恢复效果评测，因此不宣称误拒绝率已有进一步改善。

历史漂移 v2 JSON 保留不动；重现测试改为严格比较输入与结果，排除历史源码哈希，和其他历史实验采用相同方式。旧哈希仍记录产生报告时的源码，而不是当前版本证明。
