# 只读恢复诊断命令

2026-11-15。新增 `embodied_agent.evidence_audit`，将历史检查点核验、索引发现和逐条对账整合为可直接运行的命令。输出 JSON、中文处置说明及明确退出码，可被运维脚本调用。没有自动登记、写入、重放或修复行为。

```sh
PYTHONPATH=src:. .venv/bin/python -m embodied_agent.evidence_audit \
  --database /absolute/path/evidence.sqlite \
  --store /absolute/path/checkpoint.sqlite --max-records 10000
```

重新安装项目后也可使用 `embodied-evidence-audit` 入口。

| 状态 | 退出码 | 含义 |
| --- | --- | --- |
| verified | 0 | 已知历史匹配，当前扫描全部索引均已落账 |
| pending | 3 | 全部索引已扫描，但存在未落账索引，需要人工核查 |
| incomplete | 4 | 达到数量上限，仍有未扫描索引，不得视为全库通过 |
| blocked | 5 | 历史不符、损坏、缺失、路径错误等；保留原始状态处理 |

命令行语法错误由 argparse 返回 2。若已扫描部分发现损坏，即使扫描尚未完成也返回 blocked；若只发现 pending 且还有未扫描项，则返回 incomplete，counts 保留已见结果。

核对历史与分页读取在同一个源库读事务中进行，仓库读事务贯穿整个操作；不是跨两个库的分布式原子快照。每批最多 100 个条目，默认最多扫描 10000 个索引，可指定 1..100000。只输出计数而非证据正文。历史摘要校验只进行一次，但仍需读取检查点覆盖的历史，因此数量上限不等于总耗时上限。长读事务可能影响发布者提交，适合离线诊断。

`checkpoint_record_count` 与 `examined` 分别报告已知检查点记录数和本次扫描索引数；不能把当前发现的全部记录都当成已经受持久化检查点保护。verified 也不证明数据库内容真实、机器人动作成功或当前证据仍有效。未索引记录的漏查已由后续双向扫描修复，见下文。

新增 8 项测试通过，使用独立 CLI 子进程覆盖通过、只读、追加、上限、未落账、历史丢失、缺失仓库、非法参数和未覆盖尾部损坏；连同原证据链共 58 项测试通过。另复用上一轮真实进程实验保存的数据库执行两次 CLI：完整扫描返回 0，上限为 1 返回 4，输入文件哈希未改变。[运行记录](evaluations/evidence-audit-v1.json)包含输出、源文件及输入哈希。

本轮进展是将组件级恢复能力变成可调用的操作入口，并避免不完整扫描被误报为成功；没有新增实机能力或分布式一致性保证。

后续扩展：[双向一致性审计](bidirectional-audit.md)增加证据到索引的反向检查；数量上限分别应用于两个方向，任一方向未完成都不再报告 verified。
