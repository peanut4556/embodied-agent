# 预算池身份绑定与打开校验

日期：2026-11-19。

本轮修复两个明确的合同缺口：应用重启时仅凭路径无法区分原池与替换的新池；已有分配记录此前只检查请求编号非空，未复核字符串类型与长度。

`WaitBudgetStore(path, expected_pool_id=...)` 新增可选预期身份。打开时在同一读事务中读取配置、核对预期池身份并校验全部已有分配记录；每次后续分配仍在写事务中重新校验。异常时不追加记录，不自动重建或修复数据库。

```python
# expected_id 必须来自初始化时独立保存的部署配置。
# 不要先从待检查数据库读取 pool_id 再传回来，否则失去绑定意义。
pool = WaitBudgetStore(path, expected_pool_id=expected_id)
manager = CaptureRecovery(
    position_error_m=(0.001,) * 3,
    capture_profile="reserved",
    persistent_wait_budget=pool,
)
```

旧调用不传预期编号仍可用，不声称具有跨重启身份绑定。预期编号拒绝空值、非字符串及超过 256 字符的输入。已有槽位和份额必须为整数，请求编号必须为 1–256 字符字符串；顺序、份额计算和池配置继续沿用原校验。

新增四项测试使用实际临时 SQLite 数据库，验证：绑定身份重开后继续领取第二槽位；同路径替换另一池后拒绝打开；非法预期编号拒绝；已有请求编号为二进制、空或过长时，重开和继续分配均拒绝，记录数不增加。包括既有采集与恢复回归，共 63 项相关测试通过，Ruff 检查通过。

本轮没有新增完整采集性能实验，也不将此前报告当作当前源码的重新验证结果。池编号不是签名，配置需要独立保管；同一池旧数据库副本仍可能具有相同编号，因此本功能不提供防回滚、恶意篡改防护、设备互斥或硬 CPU 配额。未自动修改现有实验脚本为绑定模式，调用方需要显式传入预期身份。
