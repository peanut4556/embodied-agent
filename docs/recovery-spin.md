# 恢复后曝光等待策略：可选末段自旋

2026-11-16。上一轮恢复后两次都错过 2 ms 曝光窗口，但现有记录不足以确定 OS 调度原因。本轮提供一个可选候选策略：较远时休眠，在目标曝光前的短窗口只检查 monotonic 时钟，减少最后一次 sleep 唤醒的依赖。

```python
manager = CaptureRecovery(
    position_error_m=(0.001,)*3, capture_profile='reserved',
    supervised=True, runtime_limit_s=4, spin_window_s=0.0015,
)
```

ScheduledPairReader 与 ScheduledReaderFactory 也接受 spin_window_s。有效范围 0..0.002 秒；默认 0 完全沿用休眠策略。恢复管理器仅在 reserved 配置允许非零自旋窗口。较远时单次休眠最多 1 ms，且计划睡眠结束点不越过自旋窗口起点；进入窗口后继续读取单调时钟，直到真实目标时间到达才调用读取器。

这没有改变请求目标、最晚曝光时间、真实曝光戳核对或过期拒绝规则；OS 抢占或休眠直接越过最晚时间仍拒绝，不补采、不伪造时间戳。自旋会占用工作进程 CPU，不是无成本优化，未测得 CPU/功耗收益。

## 对照实验

```sh
make recovery-spin-check RECOVERY_SPIN_OUTPUT=outputs/evaluations/recovery-spin-new
```

沿用独立监督恢复实验：初始 factory 永久阻塞，由 4 秒时限回收，再显式切换新会话。按 A/B/B/A 顺序执行，A 为默认休眠，B 为最后 1.5 ms 自旋。每次都核对旧资源退出、旧令牌拒绝、最终确认、一次领取及次数预算。

## 结论边界

本轮交付可控的等待策略及同轮对照工具，证明该候选策略能接入完整恢复确认流程并保持合同。未证明可靠性、CPU 开销或实时性能优于默认方案，因此没有默认启用。

自旋无法阻止 OS 抢占、读取器本身阻塞或进程被暂停。冻结的自定义时钟会使等待无法完成，仍依赖外部监督时限；默认生产时钟为 monotonic。读取器依旧为合成双视角，没有实机、功耗或长期成功率结论。
