# 确认策略的固定故障矩阵

日期：2026-11-21。

本轮增加三种配置、六种场景的可复现比较，共 18 个运行。每个运行是独立的单步 verify 任务，位置与时间由确定性 fixture 生成；预设期望标签只用于评估，不传给 AgentRuntime。未训练模型、未自动修改默认配置。

场景包括持续有效状态、前两次读到反例后更新为有效状态、仅第一次正面的瞬时误报、动作前旧时间戳的成功状态、重复同一成功样本时间戳、未来时间戳。前两个预期通过，后四个是人为指定的异常反例。异常标签并非来自物理传感器真值，实验有意挑战确认合同。

| 配置 | 场景数 | 误接受异常场景 | 漏掉有效场景 |
|---|---:|---:|---:|
| 立即确认，无新鲜度限制 | 6 | 4 | 1 |
| 150 ms 等待，100 ms 新鲜度 | 6 | 2 | 0 |
| 同上，加 3 样本、30 ms 跨度、25 ms 最大间隔 | 6 | 0 | 0 |

所有 18 个运行仅调用一次 execute。新鲜度模式能拒绝旧帧和未来戳，但会立即接受瞬时误报与首次出现的重放帧；时间模式通过等待更多不同时间的样本拒绝这两个反例。稳定和延迟更新场景在时间模式下通过。每个结果保留逐步确认诊断、读取次数和终止原因。

实验前保存计划和源码哈希，输出目录不允许覆盖。首轮 v1 后修正 Ruff 提示的循环变量绑定写法，使用最终源码执行 v2；两轮结果一致，v1 原始输出保留，未因好坏结果选择性重跑。最终摘要见 [结果文件](evaluations/confirmation-faults-v2.json)，含源码及完整报告哈希。完整报告和计划位于本地忽略目录 outputs/evaluations/confirmation-faults-v2/。

新增三项测试验证矩阵完整与不重执行、时间模式对预设标签的行为、重复运行结果无跨场景污染；与主运行回归共 38 项测试通过，Ruff 检查通过。

```sh
make confirmation-faults-evaluate CONFIRMATION_FAULTS_OUTPUT=outputs/evaluations/confirmation-faults-new
make confirmation-faults-test
```

此表不是统计成功率：样本是六个刻意选择的合同用例，时钟是可控模拟，没有 OS 调度、相机、MuJoCo 或机器人。没有噪声分布、随机未知故障或独立验证集，不能声称鲁棒性已泛化。重复正面假数据若持续产生递增时间戳，仍可能满足全部合同。当前结果证明配置能够区分这些具体反例，而非保证物理真实性。
