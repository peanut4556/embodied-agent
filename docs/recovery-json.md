# 恢复文件无歧义解析

日期：2026-11-20。

本轮新增共享 recovery_json 读取器，接入启动意图、审计清单、检查点及单条对账命令。此前 json.loads 对重复键默认采用最后一个值，可能把前面已查看的请求编号、数据库路径或基线字段悄悄覆盖。现在任何层级的重复字段均拒绝，包括重复值恰好相同的情况。

输入同样拒绝 NaN、Infinity 和 -Infinity；解析结果显式检查最多 64 层，解析器自身 RecursionError 转换为可处理的 ValueError。读取继续受字符数上限约束：意图及检查点 8192，清单及批量请求列表 65536。单条 lookup_wait_budget 的检查点读取此前无上限，本轮统一补齐。深度检查在 JSON 解析后执行，并非流式硬内存限制；大小限制是字符数而非字节数。

新增四项测试覆盖重复意图编号、嵌套重复清单字段、非标准常量/深度/大小，以及实际独立命令对重复或过大检查点返回退出码 2 和 unconfirmed，数据库无新增分配。首次深度测试发现当前解释器允许 2000 层解析，随后增加显式 64 层检查；最终与相关恢复及预算回归合计 67 项通过，Ruff 检查通过。

```sh
make recovery-json-test
```

原有合法文件保持兼容；之前依赖重复键覆盖的文件现在必须修正，不自动猜测用户意图。错误沿用已有隔离方式：非法清单整批拒绝，单条意图或检查点错误标为无法确认。没有改变额度分配、采集启动或设备授权语义。

这是恢复输入合同加固，不是任务成功率或速度突破。它不提供数字签名、来源认证、通用 JSON 安全沙箱或全局防回滚；本轮未新增完整采集及实机实验。
