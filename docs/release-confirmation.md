# 释放后的独立 RGB-D 落点确认

2026-10-24。新增实验性 ReleaseConfirmation，将“发生主动释放”与“观察到物体稳定处于托盘内”分开。模块暂未接入 GuardedExecutor，不改变现有任务成功判断或恢复行为。

## 判定输入与边界

调用方在释放时创建验证器，传入起始时间；随后输入单调递增的观测时间和当前 RGB-D 位置，检测失败用 None 表示，不复用旧位置。验证器不接收模拟物体真值。

托盘内观测采用保守区域：x 距 0.64 m 小于 0.05 m、|y| 小于 0.04 m、中心高度在 0.032–0.058 m。连续位置差推算速度必须小于 0.02 m/s，相邻观测间隔不得超过 0.25 s，持续至少 1 s 才返回 confirmed_in_tray。缺失、过长间隔、离开区域或移动过快会重置持续证据。

确认窗口为 3 s。窗口结束时，当前可见位置不在区域内则返回 outside_tray；其他证据不足情况返回 unconfirmed。没有新观测时，调用方仍需周期性提交带时间的 None 才能推进超时。晚于窗口的观测不能补发成功。状态一旦结束便保持，不承担后续物体监控。

这只确认落点，不证明此前发生了有效抓取和搬运；任务验收仍需保留既有抓取、抬升、释放证据链。位置来自针对单个直立红色方块的现有 RGB-D 定位器，阈值尚未经真实相机标定。

## 六组物理对照

固定机械臂，令方块从 0.12 m 高度落下，以 5 Hz 获取真实模拟渲染图像并调用现有定位器。模拟真值仅用于审计结果，没有输入验证器。

| 初始落点 / 条件 | 视觉结论 | 结束时模拟真值 |
|---|---|---|
| x=0.64，y=0 | confirmed_in_tray | 托盘内 |
| x=0.61，y=0 | confirmed_in_tray | 托盘内 |
| x=0.69，y=0，靠近边缘 | confirmed_in_tray | 托盘内 |
| x=0.80，y=0 | outside_tray | 托盘外 |
| x=0.64，y=0.16 | outside_tray | 托盘外 |
| 中心落点，但屏蔽所有观测 | unconfirmed | 托盘内 |

六例没有出现“视觉确认而结束时真值不在托盘内”的情况；这只是小规模固定对照，不是误确认率保证。初始位置不等于最终落点，方块仍参与完整重力和碰撞模拟。缺失观测案例是显式屏蔽输入，没有模拟真实遮挡图像。

4 项新测试覆盖持续时间、丢帧、间隔、运动、迟到与非法输入；加上原有测试共 95 项通过（58 项核心、31 项接触、6 项释放相关）。Ruff 与 diff 检查通过。图形环境仍有 ARB_clip_control 深度精度提示。

机器报告：[观测序列与真值对照](evaluations/release-confirmation-v1.json)。报告保存全部采样位置、时间、检测错误、真值与源文件哈希；本轮未保存原始 RGB-D 图像，复现需重新渲染。

## 复现及下一步

```sh
make release-confirmation-test
make release-confirmation-evaluate RELEASE_CONFIRMATION_OUTPUT=outputs/evaluations/release-confirmation-new
```

需要 MuJoCo 图形连接，输出目录必须不存在。不依赖历史训练数据，也未训练新模型。下一步将其作为观测分支接到完整抓放回放，检查机械臂遮挡、倾斜物体和视觉误差是否导致误确认或超时，再决定是否用于运行时控制。

后续[完整回放观测对照](release-observer.md)发现机械臂遮挡导致确认超时；独立落点结果不能直接代表完整抓放流程的可见性。
