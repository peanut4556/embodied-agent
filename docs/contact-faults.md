# 接触监控输入故障审计

2026-10-22。本轮增加可复现的接触故障注入与独立物理评分重算，确认了两个尚未解决的边界：单帧假丢失会误触发恢复；持续假持物会阻止失败轨迹触发恢复。实验完成不代表控制器通过了传感器容错要求。

## 固定设计与注入范围

[配置](../config/contact-faults.json)固定一个已知训练初始状态 x=0.302 m、两条已有动作轨迹（正常成功 parent-baseline 与失败 replay-baseline），使用此前的插值回放器按原速执行。每条轨迹执行无监控基线，以及开启下降宽限恢复器的六个条件：无故障、第 110 帧起强制 False 1/3/25 帧、全程 False、全程 True。合计 14 次物理执行，模型未训练，恢复门槛未修改。

新增 `GuardedExecutor.step(..., monitor_holding=...)` 可选诊断参数，只替换接触丢失监控和首次抓持监控的输入；不传参数时保持原行为。原始 world、回放器输入、RGB-D 专家及 GraspQuality 继续读取真实物理状态。接管后不再消费该监控输入，人工停止优先于注入。输入必须为布尔值（或 None 使用原观察）。

**这不是整个传感器管线故障测试。** RGB-D 专家的接触输入没有被污染，回放器也不依赖该信号。恢复器能救回某个注入案例，不意味着真实共享传感器损坏时也能恢复。监控内部不使用真值纠正信号；真实接触只用于原有物理组件及独立评分。

## 结果

| 条件 | 正常轨迹：结果 / 接管帧 | 失败轨迹：结果 / 接管帧 |
|---|---|---|
| 无监控 | 成功 / 无 | 失败 / 无 |
| 监控无故障 | 成功 / 无 | 成功 / 79 |
| 第 110 帧起假丢失 1 帧 | 成功 / 110 | 成功 / 79 |
| 第 110 帧起假丢失 3 帧 | 成功 / 110 | 成功 / 79 |
| 第 110 帧起假丢失 25 帧 | 成功 / 110 | 成功 / 79 |
| 持续 False | 成功 / 100 | 成功 / 100 |
| 持续 True | 成功 / 无 | **失败 / 无** |

正常轨迹的三个短暂假丢失条件都在首个错误帧接管；接管后监控停止消费信号，因此三者有效改变的监控输入均只有 1 帧。不能把它们写成“恢复器承受了连续 25 帧故障”。失败轨迹原本第 79 帧已经接管，所以第 110 帧开始的三个故障均未实际作用于监控，报告明确记录有效故障帧数为 0。

持续 False 导致首次抓持门槛在第 100 帧接管，两条轨迹由未受污染的 RGB-D 专家完成；正常基线本可成功，所以这一接管并非挽救失败。持续 True 在失败轨迹中掩盖接触丢失，并使首次抓持监控认为已建立稳定抓持；30 秒内没有完成，真实物理评分仍为失败；预算到达时显式停止并记录 execution timeout。持续 True 的正常轨迹成功来自原动作，不是监控器修复了错误信号。

这些是同一场景的确定性诊断，不给出总体成功率，不改变此前 14/16 的空间回归成绩，也未重新运行该网格。本轮没有加入去抖或故障检测规则：单纯延迟接触丢失响应可能破坏原第 79 帧及时接管的收益，需要另行设计配对验证。

## 评分独立性与校验

每个控制周期保存实际 qpos、qvel、上一条 ctrl、实际接触、注入接触、监控是否仍在消费输入及新命令。结束后用一个新的 PhysicsWorld 恢复这些物理状态，重新计算接触与入盒条件，再独立运行 GraspQuality；14 条轨迹的完整评分和事件均与运行时一致。注入值不参与这一重算，持续假持物没有被误报为成功。

12 个监控条件与对应无监控基线的接管前动作、qpos、真实接触逐值一致；未接管时比较全程。14 条轨迹的哈希、有限命令及物理评分重算通过，源代码运行前后哈希一致。6 项新增注入测试、21 项监控回归、58 项核心测试共 85 项通过；Ruff 与 diff 检查通过。未做网页/ROS 或真机联调。MuJoCo 本地图形驱动继续提示 ARB_clip_control 不可用，深度精度限制与此前相同。

[机器报告](evaluations/contact-faults-v2.json)保存逐例结果、真实质量事件、有效故障帧数和哈希；原始 NPZ 位于 outputs/evaluations/contact-faults-v2/，未纳入 Git。默认控制台不启用故障注入。

## 复现

```sh
make contact-faults-test
make contact-faults-evaluate CONTACT_FAULTS_OUTPUT=outputs/evaluations/contact-faults-new
```

需要本地历史轨迹、初始状态清单及 MuJoCo 图形连接。输出目录必须不存在，输入哈希不匹配或评分重算不一致将拒绝/中止运行并报告失败。后续应比较去抖与接触一致性检查，在保留真实接触丢失恢复时效的前提下处理假丢失和假持物。
