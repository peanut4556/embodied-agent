# 连续新鲜样本确认

日期：2026-11-21。

AgentRuntime 新增 confirmation_samples（默认 1，范围 1–10）。大于 1 时必须同时配置新鲜度、正确认等待时限，且读取次数上限不少于样本数。默认单样本行为不变。

每个动作仍只执行一次。多样本模式要求连续符合后置条件的新鲜观测，并且取样时间严格递增才增加计数。重复时间戳的正面观测既不增加也不清零；任意不符合条件或不新鲜的观测清零。相邻返回样本时间戳倒退立即拒绝。计数达到阈值才完成该步骤，超时、取消、读取次数上限仍然生效。

```sh
PYTHONPATH=src .venv/bin/python -m embodied_agent '把桌上的红色积木放进盒子' --confirmation-timeout .5 --max-observation-age .1 --confirmation-samples 3
```

本轮还修复上一轮 CLI 接线遗漏：max-observation-age 参数原先虽被解析，却未传入 AgentRuntime，也未选择 TimestampedMockRobot。此前 API 测试有效，但 CLI 命令成功不能证明该模式已启用；原文档已追加更正。现在参数、带时间戳 mock 和样本数均显式传入，并有专门接线测试。

新增 6 项测试覆盖不同样本确认、重复帧无法累计、反例清零、时间戳倒退、非法配置及 CLI 参数传递。与既有主运行回归共 26 项通过，Ruff 检查通过。实际每步三样本命令完成四步 mock 任务。

```sh
make runtime-confirmation-test
```

时间戳来自适配器，多个不同戳不证明数据独立或内容真实，也未规定最小样本间隔或稳定持续时间。轮询间隙可能存在未观测变化，因此不等于连续物理稳定。时间戳倒退策略偏保守，适配器需自行处理乱序。没有相机、MuJoCo 或实机性能实验，不能据此宣称成功率提高。
