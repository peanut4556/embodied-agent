# 显式采集恢复与跨会话证据隔离

2026-11-13。在[可终止的采集进程后端](process-pair-capture.md)之上新增 `CaptureRecovery`，将故障退出、退出核验、新会话预热和新任务创建串成有界生命周期。没有自动重放任务、接入真实相机或切换默认执行端。

## 恢复合同

调用方显式 `start(factory)` 才会创建一轮新会话；最多允许 1–3 轮，启动失败也消耗次数。

1. 活跃任务仍 pending 时禁止 start。必须先明确停止或关闭，不能把仍运行的任务直接替换掉。
2. 对上一轮执行取消和有界回收，要求入口已关闭、无存活工作进程、每个进程退出码均已核实。否则状态为 `cleanup_pending`，返回 None，绝不调用新工厂。稍后可再次关闭/回收。
3. 为新轮次生成 UUID 会话标识，创建全新的进程和 IPC，完成预热后才启动新任务时钟。
4. 新控制器从空请求列表和空见证状态开始，不继承旧候选、旧位置、旧计时或旧确认。请求编号可以在新会话重新从一开始，但会话标识不同。
5. step 必须携带本轮 token。旧会话的轮询或停止请求被忽略并计数，不能取消新任务；新驱动若返回旧 session，原控制器拒绝该观测。

工厂初始化失败时保存回收记录，允许在剩余预算内显式启动新轮次。若进程构造函数直接抛错，部分 OS 资源归属可能不明确，管理器锁定为 `ownership_uncertain`，拒绝再次启动；不能仅因异常已经抛出就推断没有存活子进程。

`close()` 可显式结束活动任务并回收；未核实回收时返回 False，不伪报成功。历史记录最多三轮，包含会话、轮次、最终证据与退出码。运行器抛错时仍会同步生命周期为终态，不能留下“运行中”的误导状态。

这里的恢复仅证明软件进程隔离和任务状态重建，结果明确带有 `hardware_recovery_verified=false`。真实设备是否可以重新打开、是否需要复位、位置误差是否仍有效，需要驱动层另行确认；不应把本管理器作为硬件恢复就绪判断。

## 真实进程检查

三种场景各运行两轮进程会话：

- 忽略 SIGTERM 的卡住读取 → 显式启动快速读取。
- 工厂初始化异常 → 显式启动快速读取。
- 卡住读取 → 新驱动故意返回旧会话标识。

每次恢复都断言：旧进程已全部退出、旧管道无可消费结果、新会话 token 不同、新控制器没有旧请求或见证、旧 token 的停止不影响新 pending 状态。最后关闭新轮次并核实所有进程退出。

| 场景 | 首轮检查 v1 的新任务结果 | 最终检查 v2 的新任务结果 |
| --- | --- | --- |
| 卡住后快速读取 | 36 请求，确认通过 | 30 请求，曝光超计划窗口拒绝 |
| 初始化失败后快速读取 | 36 请求，确认通过 | 17 请求，曝光超计划窗口拒绝 |
| 新驱动返回旧 session | 首个请求 `camera_session_changed` | 首个请求 `camera_session_changed` |

两轮检查的旧进程回收、新会话隔离断言都通过。v1 后补充运行器异常的生命周期同步，v2 使用最终源码重新运行；两份报告都保留，没有通过挑选成功运行宣称稳定可靠。

**会话重建成功不等于新任务能满足严格采集时序。** 本地真实调度仍可能使曝光超过 2 ms 容忍窗口；v2 的两个拒绝没有被重试或延长门槛挽回。合成读取的完整通过也不证明实际相机能够满足同样的误差和延迟要求。

每个报告包含旧会话退出码、kill 升级标记和新会话结果，可检查新进程创建之前已经回收旧进程。PID 可能被操作系统复用，隔离身份依赖 UUID 与独立 IPC，不依赖 PID 永不重复。

## 使用示例

```python
manager = CaptureRecovery(position_error_m=validated_error_budget, max_generations=2)
try:
    token = manager.start(camera_factory)
    if token is not None:
        while manager.step(token) == "pending":
            schedule_next_poll()
    # 仅在调用方决定恢复且设备驱动确认可重开时，再显式 start。
    # 不把旧动作、旧候选或旧成功标志自动带入新任务。
finally:
    fully_reaped = manager.close()
```

管理器方法由一个控制线程调用；预热和回收不是伺服热路径。调用方仍负责观察返回值、停止真实设备动作及处理硬件状态。
