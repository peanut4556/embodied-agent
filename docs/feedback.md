# 视觉与夹持反馈执行

本阶段为冻结的视觉条件回归策略增加反馈控制规则，使用当前 RGB 图像、五个关节编码器
位置和双指夹持接触信号，处理抓取前目标位移与抓取失败。模型权重没有重新训练。
这是“学习模型＋规则控制器”的混合反馈执行，不是端到端闭环学习策略。

## 执行流程

1. 用首帧 RGB 和已有模型生成动作序列，按 25/50 Hz 执行。
2. 接近开始的前 0.6 秒内约每 0.2 秒检查画面。可靠的红色区域质心变化超过 2 像素时，
   退回初始观察姿态。由于机械臂可能遮挡目标，暂时无法识别的帧不直接判定目标消失。
3. 在每次尝试的 4.72 秒处，即现有演示抬起结束附近，检查双指夹持。若没有夹住，
   取消剩余动作，退回观察位；关节稳定连续 3 帧后重新拍摄并生成新的模型动作序列。
4. 最多重试两次。单次退回超过 3 秒、目标识别失败或超出模型训练范围时停止。
5. 用户停止与无效关节观测会锁定停止状态，不再消费旧动作或自动重新规划。
   停止时保持当前机械臂关节位置目标，保留夹指控制目标。

退回使用初始关节姿态，机械臂目标变化限制为 2 rad/s，夹指目标变化限制为 1 m/s，
均在执行器控制范围内。它没有使用 IK 计算恢复路径，也不调用专家 `pick/place/locate`。
这些参数仅用于当前简化仿真机械臂，不对应真机执行规范。

双指夹持信号来自仿真接触检测，是模拟触觉，不是已接入真实传感器。
规则中的 4.72 秒检查点与现有演示时序绑定；更换动作节奏需要重新校准和评测。

## 复验

需要上一阶段的 `outputs/models/context-bc-v1` 模型以及 MuJoCo 渲染环境。

```bash
# 开发场景，用于检查实现
PYTHONPATH=src .venv/bin/python scripts/evaluate_feedback.py \
  --group development --output outputs/evaluations/feedback-dev-new

# 保留测试：相同场景分别运行开环与反馈执行
make feedback-evaluate FEEDBACK_OUTPUT=outputs/evaluations/feedback-test-new
```

场景定义见 `config/feedback-scenarios.json`。开发组包含早期视觉位移与两个较晚位移场景；
测试组包含 2 个正常场景、4 个位移场景和 3 个停止场景。参数在保留测试之前冻结。
输出路径必须不存在，不覆盖旧结果。

独立评测脚本用于成对比较；同一反馈控制器现已接入 ROS 2 控制台，见下文。
模型只接收图像；反馈控制器额外接收关节状态和夹持信号。场景真值坐标只用于
测试初始化、注入扰动和最终验收，不传给模型或反馈控制器。

**扰动使用评测夹具直接重新放置自由积木，并清零其速度**，模拟外部重定位事件。
它不是施加推力产生的动力学扰动；被移到桌外的物体继续自由下落。
控制器自身不会修改积木位姿。这项实验只能说明对此类目标重定位的恢复能力。

## 本次结果

冻结的保留测试输出在 `outputs/evaluations/feedback-test-v1`：

| 场景 | 开环 | 反馈执行 |
| --- | --- | --- |
| 2 个正常抓放 | 2/2 成功 | 2/2 成功 |
| 4 个目标位移 | 0/4 成功 | 4/4 成功，均重试一次 |
| 目标超出训练范围 | 继续执行至轨迹结束 | 停止 |
| 目标移出视野 | 继续执行至轨迹结束 | 停止 |
| 用户停止 | 停止 | 停止 |

抓放总计：反馈 6/6，开环 2/6。反馈停止检查 3/3，通过条件包括停止状态、
目标保持不变，以及最后 5 帧关节变化小于机械臂 0.01 rad、夹指 0.001 m。
四个位移场景耗时约 16.6–16.9 秒，正常场景约 11.5 秒，均包含一秒终态稳定观察。
轨迹执行结束的 `completed` 与物理任务成功的 `success` 分别记录，不能混为一谈。

`evaluation.json` 保存事件、重试次数、停止原因、最终状态和模型/场景文件哈希；
`partial-results.json` 保留已经完成的场景记录。每个场景的 GIF 左边为开环，右边为反馈执行；
较早结束的一侧保留其最后画面。数据及动画保留在本地 `outputs/`。

新增单元测试覆盖：最新画面重规划、正常完成、重试上限、停止不自动恢复、
无效观测和初始目标缺失。

## 当前边界与下一步

视觉检查主要发生在早期接近和退回观察位之后，夹持验收在抬起结束时执行。
这一版尚不能处理任意时刻的扰动，尤其不保证抓住后运输途中滑落的恢复，也没有
在线学习新的动作。后续应接入连续夹持监测，采集实际推力扰动和恢复演示，
再训练包含连续观测的策略，并使用新的独立测试场景评估。

## ROS 2 控制台

已有 `outputs/models/context-bc-v1/policy.npz` 和 `training.json` 时，先停止旧仿真容器，
再在项目根目录运行：

```bash
make physics-feedback
# 另一个终端；若旧控制台还在运行，需要先核对并停止旧进程再启动
make sim-web-background
```

`BC_MODEL` 可指定其他模型目录。权重以只读目录挂载到容器的 `/models/context-bc`，
`SIM_POLICY_DIR` 指向它；不会将训练数据或权重打包进镜像或提交到 Git。
没有权重时，`make physics-ros` 仍可使用预设轨迹。网页会禁用未配置的学习选项；
文件存在只表示已配置，实际加载时还会校验模型结构、物理 XML 哈希和执行器范围。

打开 <http://127.0.0.1:8765>，点击重置，在“执行方式”选择“学习模型 · 视觉与接触反馈”。
规划方式可选规则或本地 Qwen。仅接受可选的红色积木定位、抓取红色积木、放入盒子、
验收这组完整计划，允许末尾停止并实际发送 ROS 停止指令。`verify.destination` 可省略或为 null，
与原执行端的默认盒子验收语义一致。先经过 `SafetyGate`，再严格编译为 `learned_pick_place` 内部技能；
不支持的对象、额外动作或缺失验收会在运动前拒绝，不会回退为预设轨迹。
原始计划和实际执行步骤分别保存并显示。学习模式同样需要从示范的观察姿态开始；
每次新任务前重置场景。

模型与控制器读取 320×240 RGB、关节位置及双指接触，以模型记录的 25/50 Hz 运行。
高层计划中的 RGB-D 定位可单独执行，但定位坐标不作为学习模型输入。
结束时独立检查物体是否稳定入盒且夹爪松开；轨迹走完不直接等于任务成功。
状态 Topic 附带本次任务编号、控制状态、恢复次数、事件和停止原因，重置后清空。

恢复执行最多 30 秒仿真时间。考虑渲染速度，学习技能的 ROS 指令有效期为 90 秒墙钟时间，
网关等待 92 秒、控制台等待 95 秒；原有预设指令仍为 20/22/25 秒。
用户停止打断当前技能、保持关节目标，并拒绝同一任务后续指令。时间到期也会停止，
即便浏览器已关闭仍由 ROS 执行层处理。
