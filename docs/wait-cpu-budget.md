# 等待 CPU 预算自动回退

日期：2026-11-18。

本轮从等待策略测量推进到实际运行行为：为 `ScheduledPairReader` 和可跨 spawn 传递的 `ScheduledReaderFactory` 增加可选 `wait_cpu_budget_s`。同一个读取器累计等待线程 CPU 达到预算后，后续请求的有效自旋窗口变为 0，继续按原预约时间休眠和校验曝光。

## 行为与范围

- 默认 `None`，保持原策略；允许有限数值 0–1 秒，0 从首个请求就不自旋，拒绝布尔、负数、NaN、无穷和越界输入。
- 显式预算自动启用等待计时；累计的是整个等待段的线程 CPU，不只是自旋，也不包括实际读取器执行及后处理。
- 每个请求开始时检查累计值，耗尽后只对后续请求回退。当前等待可能越过预算，后续休眠也仍有 CPU 开销，因此这不是总 CPU 硬上限，也不能承诺最多超出固定时长。
- 错过窗口、等待时钟异常等等待失败也计入成本；时钟异常保留原异常并清空该次可交付遥测。实际读取失败前的等待已经记账。
- 预算绑定读取器生命周期，不因 request/session 改变而补充；新建读取器有新预算，不是跨进程、跨恢复代数的全局配额。
- 遥测增加有效自旋窗口、配置预算、累计等待 CPU、耗尽状态。预算耗尽不重试、不改写曝光时间、不放宽 2 ms 校验门槛。
- 本轮接入预约读取器及独立探针；未向恢复管理器或控制台增加预算配置入口，未自动启用生产自旋。

使用示例（显式实验配置）：

```python
ScheduledReaderFactory(
    factory,
    spin_window_s=0.0015,
    measure_wait=True,
    wait_cpu_budget_s=0.005,
)
```

## 固定实验

实验前保存计划和六个源码摘要。使用新输出目录，固定 A/B/C/C/B/A 六组，每组 36 个独立窗口；A 是休眠，B 是持续末段 1.5 ms 自旋，C 是同样自旋但每读取器累计等待 CPU 预算 5 ms。预算是事先选定的演示阈值，不是从结果挑出的最优值。

真实进程、时钟、IPC 和独立监督，位置数据为合成；没有额外 CPU 负载。每组新建读取器，预算独立。失败仍进分母，缺测或清理未确认导致命令失败。逐条核对实际有效策略符合上一请求累计值，核对累计成本增量；预算组还必须实际发生回退。逐组保存结果，不按结果重跑。

| 策略 | 交付 / 计划 | 平均等待线程 CPU（ms/窗口） | 最大目标迟到（ms） |
|---|---:|---:|---:|
| 纯休眠 | 72/72 | 0.1984 | 0.2772 |
| 持续自旋 | 72/72 | 1.4133 | 0.0155 |
| 5 ms 预算后回退 | 72/72 | 0.3369 | 0.2911 |

216/216 遥测完整，6 组进程回收均确认。两个预算组都在第 4 次等待后达到阈值，第 5–36 请求使用休眠；策略轨迹和累计成本校验全部通过。

预算组平均等待 CPU 相比持续自旋降低约 76.2%，但比纯休眠高约 69.8%。每个预算组最终总等待 CPU 约 12.1 ms，这与 5 ms 的回退阈值不矛盾：当前请求越过阈值，回退后的等待仍消耗 CPU。本轮三种策略交付相同，不存在已证明的成功率提升。

## 验证及限制

44 项相关测试通过，涵盖预算回退、跨会话不补充、零预算、失败计费、输入合同、工厂传递，以及原曝光时序、进程、恢复、遥测与固定分母回归。首次测试编排从 stdin 启动，导致 spawn 无法导入 `<stdin>`；改用下面的标准模块入口后通过，无需修改实现修复该运行方式错误。Ruff 与源码/报告哈希检查通过。

这是成本控制能力的接入验证，短时、单机、合成数据；不是硬实时保障、能耗测量或实机成功率。不能用两组预算实验宣称稳定改善。回退可能增加后续错窗风险，因此仍显式可选，纯休眠默认保持不变。后续若接入完整恢复任务，应明确跨代预算语义，并测试回退对完整确认的影响。
