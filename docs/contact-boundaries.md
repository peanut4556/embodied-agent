# 一致性检查的释放滞后与闭爪假持物边界

2026-10-22。本轮固定上一版控制器，扩展故障注入工具，验证何时会过早停止以及何时检测不到异常。结果表明该检查不能默认启用：正常释放的监控信号滞后 3 帧即可触发提前停止；只在闭爪命令期间出现的假持物不触发一致性错误。

## 预先固定的对照

[配置](../config/contact-consistency-boundaries.json)校验控制器文件、上轮报告、初始状态与两条动作轨迹的 SHA256。使用同一已知训练场景的正常/失败动作回放，分别关闭和开启 contact_consistency。每组包含无监控基线，以及 nominal、释放滞后 1/2/3/6 帧、闭爪期间假持物六种条件；每组 14 次，共 28 次物理执行。全程不调整检测门槛，不训练模型。

新增 ContactFaultSignal 两种状态相关注入：

- release_lag：真实接触从 True 变为 False 且双指命令均张开时，监控输入额外保持 True 指定帧数；初始没有持物时不会凭空制造一次释放，闭爪期间真实滑落也不触发该注入。
- closed_only：只有双指命令均小于 0.01 m 时强制监控输入为 True，其余时刻使用原值。

注入依据真实状态构造实验信号，不向控制器提供真值修正。仅污染两个接触监控器的输入，回放器、RGB-D 专家及物理评分仍读取原状态。接管后监控不再消费信号；这不是完整传感器管线容错验证。

## 结果

正常动作回放的结果如下，帧编号从 0 开始：

| 条件 | 一致性检查关闭 | 一致性检查开启 |
|---|---|---|
| 无监控基线 | 成功 | 成功（重复基线） |
| nominal | 成功，不接管 | 成功，不接管 |
| 释放滞后 1 帧 | 成功，不接管 | 成功，不接管 |
| 释放滞后 2 帧 | 成功，不接管 | 成功，不接管 |
| 释放滞后 3 帧 | 成功，不接管 | 第 193 帧异常停止，验收未完成 |
| 释放滞后 6 帧 | 第 197 帧接管后成功 | 第 193 帧异常停止，验收未完成 |
| 闭爪期间假持物 | 成功，不接管 | 成功，不接管 |

真实物理评分在第 191 帧已记录主动释放。开启检查的 3/6 帧滞后案例在第 193 帧停止，此时尚未满足一秒稳定入盒要求，因此评分为 task_incomplete，而不是 verified_pick_place。审计按停止时结束执行，**没有继续观察到物体最终稳定状态，不能据此断言物体最终一定掉出托盘**。这里证实的是控制流程提前终止验收。6 帧滞后在关闭检查时也会误触发旧接触丢失恢复，最终成功不代表不存在不必要干预。

失败动作回放在无故障时仍第 79 帧接管并成功；四种释放滞后注入都晚于接管，有效故障帧数为 0，不能记作四个成功抗故障案例。闭爪假持物实际改变了 3 次监控观测，使接管推迟至第 83 帧，两组均成功，但都未产生 contact_inconsistent。它揭示一致性条件的盲区；本例仍由原接触丢失路径救回，不证明所有闭爪假持物都可恢复。

两组间 12/14 条轨迹全程逐值一致，只有正常轨迹的释放滞后 3/6 帧案例改变。所有条件共享一个物理初始场景，不给总体容错率，不更新此前空间网格成绩。

## 校验与交付

28 条轨迹均通过真实接触及 GraspQuality 独立重算、干预前基线一致性、哈希和有限命令检查；两次运行源代码哈希一致且结束时未改变。新增 6 项故障模型测试，覆盖准确滞后长度、接触丢失不误当释放、窗口边界/实例隔离、闭爪条件、旧注入兼容及配置拒绝。全部 28 项接触相关测试和 58 项核心测试通过，共 86 项。Ruff 与 diff 检查通过，未做网页/ROS 或实物联调；本地 MuJoCo 仍有 ARB_clip_control 深度精度提示。

机器报告：[关闭检查](evaluations/contact-boundaries-off-v1.json)、[开启检查](evaluations/contact-boundaries-on-v1.json)、[逐项比较](evaluations/contact-boundaries-comparison-v1.json)。原始轨迹在 outputs/evaluations/contact-boundaries-off-v1/ 和 contact-boundaries-on-v1/，未纳入 Git。默认控制器及控制台行为未改。

```sh
make contact-boundaries-test
make contact-boundaries-evaluate \
  CONTACT_BOUNDARIES_OFF_OUTPUT=outputs/evaluations/contact-boundaries-off-new \
  CONTACT_BOUNDARIES_ON_OUTPUT=outputs/evaluations/contact-boundaries-on-new
```

需要本地历史轨迹及 MuJoCo 图形连接，输出目录必须不存在；控制器或输入哈希变化时拒绝运行。本轮证据支持下一步区分正常释放阶段的滞后与初始假持物，再用这些已见案例回归及新的冻结条件验证；不能通过简单增大所有接触丢失的等待时间来宣称问题已解决。
