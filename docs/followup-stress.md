# 后续监测的延迟、掉帧与故障组合验证

2026-11-02。新增可重复的确定性采集会话模型，将延迟、掉帧、区域变化与运行故障组合，检验 ProcessPostConfirmation 的告警时刻、终态和终态后请求行为。本轮没有修改监测算法。

## 108 场景矩阵

| 维度 | 取值 |
| --- | --- |
| 请求到结果延迟 | 31.25、125、281.25 ms |
| 位置序列 | 持续区域内、持续区域外、仅第 3 次请求区域外 |
| 掉帧模式 | 不掉帧、每第 3 次请求返回 None、全部 None |
| 注入故障 | 无故障、主机时钟跳变、采集崩溃、用户停止 |

共 3×3×3×4 = 108 个场景。模型每 1/64 秒调度一次，监测任务窗口为 [1, 3) 秒，曝光设在请求到完成的中点，请求超时为 250 ms；时钟跳变、崩溃或停止在任务时间 1.5 秒注入。长延迟请求会在更晚故障发生之前先超时，预期终态按先发生的事件计算。

采集会话模型记录每个实际交付的曝光。独立参考函数枚举连续区域外曝光窗口，排除 None、区域内帧以及大于 250 ms 的曝光间隔，计算首次覆盖至少 250 ms 的告警时刻。参考函数不读取监测器的累计状态，但使用相同的合成交付记录；它不独立验证请求调度是否产生了所有理想帧，也不是通用空间几何验证器。

每个场景还核对：预期状态与原因、终态后再调一次 step 不增加 poll/request、清理状态完成、原始 confirmed_in_tray 快照保留。

## 结果

[保存的 108 场景结果](evaluations/followup-stress-v1.json)：

| 项目 | 结果 |
| --- | ---: |
| 判定或首次告警时刻不一致 | 0 |
| completed | 18 |
| invalidated | 72 |
| cancelled | 18 |
| 曾记录区域外告警 | 8 |
| 终态后仍有新增请求/轮询 | 0 |

这些是按故障注入设计得到的计数，不是硬件可靠性或任务成功率。历史告警在随后停止、崩溃或时钟失效后仍保留；当前监测状态则进入相应终态。

验证再次明确了观测覆盖限制：125 ms 采集周期下，每第三次请求缺失，会不断打断区域外证据，持续区域外也可能没有告警。这符合当前连续证据要求，不能将“无告警”解释为“始终区域内”。短暂区域外单帧也不会被拼接成持续告警。

## 复现与范围

```sh
make followup-stress-test
make followup-stress-audit
```

默认输出 outputs/followup-stress-v2.json，可通过 FOLLOWUP_STRESS_OUTPUT 指定新路径。已有文件不会覆盖。每项结果包含延迟、模式、期望/实际状态与告警时刻、请求数量和终态检查；发现不一致时额外保存交付轨迹及监测快照。

新增 6 项测试覆盖完整矩阵、无误告警组、周期掉帧导致证据不足、超时优先于更晚故障、历史告警保留，以及参考窗口对缺失/区域内/超长间隔的拒绝。相关回归共 243 项通过（58 核心、31 接触、34 释放、13 线程采集、14 曝光、7 采集进程、8 进程恢复、39 恢复相关、9 独立后续监测、10 进程后续监测、20 后续边界与压力测试），Ruff 与差异检查通过。

本矩阵使用会话模型，close 只模拟关闭状态，不验证实际进程回收；回归中的既有真实 spawn 测试另行覆盖回收。没有连接真实设备，也没有新增物理抓放或训练。随机延迟分布、图像识别误差和任意时钟故障尚不在这 108 项组合中。

后续已加入[观测覆盖诊断](followup-coverage.md)：保持原判定不变，另外报告有效曝光区间覆盖比例、最长未覆盖区间及缺失/拒绝/过期计数。
