# 冻结恢复器的新速度验证与停止检查

本轮保持下降宽限控制器不变，先固定 [验证配置](../config/recovery-validation.json)，再运行此前未用于调参的八个时长倍率：1.1、1.4、1.6、1.9、2.1、2.4、2.8、3.0。配置排除上一轮已观察的七个倍率，并校验历史报告、初始状态清单、输入轨迹及控制器文件 SHA256。报告保存配置和执行代码哈希，结束时再次检查代码未改变。

这只是**同一已知训练场景下的新速度条件**，并非新物体、新空间位置或学习策略泛化评估。初始状态与轨迹来源沿用[上一轮正对照](descent-recovery.md)，无监控组采用动作插值回放，不调用学习模型。控制器没有根据本轮结果调整。

## 结果：24 次配对执行

| 时长倍率 | 无监控合格抓放 | 固定 4 秒接管帧 | 下降宽限接管帧 |
|---|---|---:|---:|
| 1.1 | 成功 | 无 | 无 |
| 1.4 | 成功 | 100 | 无 |
| 1.6 | 成功 | 100 | 无 |
| 1.9 | 成功 | 100 | 无 |
| 2.1 | 成功 | 100 | 无 |
| 2.4 | 成功 | 100 | 100 |
| 2.8 | 成功 | 100 | 100 |
| 3.0 | 成功 | 100 | 100 |

三组均完成 8/8 合格抓放；固定门槛的不必要接管为 7/8，下降宽限为 3/8，少 4 次。没有丢失基线成功，也没有“救回失败”样本，因为无监控组全部成功。不得把所有接管后的成功计作挽救失败。16 组对照的接管前轨迹一致；没有接管时比较全程动作、qpos、末端位置与接触信号，均完全一致。

2.4、2.8、3.0 倍时长仍被不必要接管，说明该规则对极慢接近阶段的覆盖有限。没有为消除这些结果延长等待或放松门槛。此前 14/16 的空间网格恢复成绩本轮未重跑：控制器文件保持不变，新实验补充的是速度与停止证据，不是一次新的空间回归。

## 三个实际停止检查

使用真实 MuJoCo 物理状态和实际 GuardedExecutor，分别验证：

| 条件 | 时长倍率 / 停止帧 | 停止前状态 | 检查 |
|---|---|---|---|
| 接管前停止 | 1.6 / 90 | 无接管 | 通过 |
| 宽限中停止 | 1.6 / 110 | 已观察宽限、无接管 | 通过 |
| 接管后停止 | 3.0 / 110 | 第 100 帧已接管 | 通过 |

每个场景停止后继续推进 25 个物理周期，检查从停止帧起共 26 帧命令完全相同、reason 为 user stop、学习器调用次数不再增长。接管前/宽限中均未触发专家；接管后学习器仍仅运行 100 帧。检查没有把“命令不再变化”当作机械臂瞬时静止或硬件急停，也未测量真机制动距离。

## 验证与复现

合计 27 次物理执行、16 组配对及 3 次停止检查通过；27 条轨迹的哈希和命令有限值检查通过。新增 3 项配置/分类/停止参数测试、8 项下降监控回归和 58 项核心测试，共 69 项通过；Ruff 与 diff 检查通过。未进行网页/ROS 或真机测试。MuJoCo 仍提示 ARB_clip_control 不可用，深度精度限制与先前环境相同。

[机器报告](evaluations/recovery-validation-v1.json)包含固定配置、源码与输入哈希、逐例质量事件、接管时机和停止检查。原始 NPZ 在 outputs/evaluations/recovery-validation-v1/，未进入 Git。此次只扩展诊断运行器和验证工具，默认控制台行为不变。

```sh
make recovery-validation-test descent-recovery-test
make recovery-validation-evaluate RECOVERY_VALIDATION_OUTPUT=outputs/evaluations/recovery-validation-new
```

需要本地历史轨迹、初始状态和 MuJoCo 图形连接；输出目录必须不存在。输入/控制器哈希变化时拒绝运行。运行过的速度从此成为已观察条件，后续调参不能继续将本轮当作独立测试。
