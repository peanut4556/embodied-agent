# 连续夹持判定与同接管点恢复对照

## 改动

新增可选专家模式 `stable-contact-v1`。采集器从自主执行开始逐帧记录连续 holding 次数，
中断立即归零，接管时包含当前帧；25 Hz 下至少 3 帧（按控制周期计 0.12 秒），
50 Hz 下至少 6 帧，且当前仍 holding，才选择保持夹持撤退。
未达到门槛时按未稳定抓取处理，沿原撤退动作张开手指，再重新感知和抓取。
这只是接管分支的保守门槛，不保证后续搬运稳定，也不是力闭合证明。

原 `legacy` 模式及默认行为保留，保证原采集计划可复现。新模式由独立配置显式开启。
没有修改模型观察、动作输出、物理、成功判据或控制台策略；没有使用物体真值判断稳定性。
每条记录新增模式、实际连续帧数、门槛和是否保留夹持的决策信息。

## 固定对照结果

父模型、训练位置 x=0.302 m、接管时间、专家其余参数均不变，没有重新选择有利接管点。
六条接管 qpos、qvel、上一控制量均匹配原自主轨迹；连续夹持帧数也用源轨迹独立复核。

| 接管帧 / 秒 | 连续 holding 帧数 | 原专家 | 连续夹持判定 |
| --- | --- | --- | --- |
| 75 / 3.00 | 0 | 成功 | 成功 |
| 77 / 3.08 | 0 | 成功 | 成功 |
| 78 / 3.12 | 1 | 失败 | **成功** |
| 79 / 3.16 | 0 | 成功 | 成功 |
| 82 / 3.28 | 1 | 失败 | 失败：视觉目标尺寸不一致或严重遮挡 |
| 84 / 3.36 | 0 | 失败 | 失败：视觉目标尺寸不一致或严重遮挡 |

合格恢复从 **3/6 提高到 4/6**，原有三条成功保留。新数据包含 2023 帧，
四条成功各提供 311 帧专家监督，共 **1244 帧**，比原对照多 311 帧。
失败轨迹保留但 mask 为零，实际训练读取仅返回 episode 0、1、2、3。

第 78 帧原来因一次 holding 为真选择保持夹持搬运，后来丢失接触；
现在选择张开撤退再抓取，完整质量判定通过。第 82 帧也改变了分支，但仍未成功，
故连续夹持门槛只修复了这组固定场景中的一个案例。4/6 是专家恢复率，不能宣称
学习策略成功率提高或在未见状态上泛化。本轮没有训练、验证位置或预留测试。

## 验证与复现

- `make contact-stable-record`：采集新模式六条轨迹，物理回放验证并生成报告，拒绝覆盖已有数据。
- `make contact-stable-compare`：验证两组数据哈希、固定计划、父模型及真实连续接触历史，生成对照报告。
- `make contact-stable-test contact-recovery-test` 和
  `make correction-test CORRECTION_DATASET=outputs/datasets/corrections-contact-stable-v1`：共 16 项测试通过。

测试覆盖瞬时接触、连续帧门槛、接触中断后的当前状态、25/50 Hz、原模式兼容、固定接管计划、
成功判据与监督隔离，以及真实数据篡改后拒绝加载和重新验证。代码风格及差异检查通过。
六条数据全部通过执行动作的严格物理回放，成功轨迹通过训练读取器的完整历史与监督边界校验。

新数据在 `outputs/datasets/corrections-contact-stable-v1`，原数据保持不变。
详见[逐轨迹报告](evaluations/contact-stable-v1.json)和[同接管点对照](evaluations/contact-expert-comparison-v1.json)。
新数据仍只有一个训练位置，不能作为当前微调入口的唯一纠正来源；仍需同采集模型的验证数据。
