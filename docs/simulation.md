# 可视化桌面仿真

同一控制台现也支持 [MuJoCo 物理模式](physics.md) 和
[学习模型反馈执行](feedback.md#ros-2-控制台)。下面的启动方式与限制特指二维快速演示。

这是运行在 Mac + Docker 上的二维两连杆运动学演示。输入中文任务后，本机 RAI/Qwen
生成结构化计划；ROS 2 仿真节点按预设轨迹执行，浏览器展示观测 Topic 中的实际状态。

## 启动

先启动 Docker Desktop 和 Ollama（已安装 `qwen3.5:4b`）。在项目根目录的两个终端中分别运行：

```bash
make sim-ros
```

```bash
make sim-web
```

也可用 `make sim-web-background` 独立后台启动控制台，日志和 PID 保存在
忽略提交的 `outputs/sim-web.log` 和 `outputs/sim-web.pid`。关闭它时先核对 PID
对应 `embodied_agent.sim_app` 进程，再使用 `kill <PID>`。

打开 <http://127.0.0.1:8765>，保留默认任务“把桌上的红色积木放进盒子”，点击执行。
“规则计划”可在无需模型的情况下测试执行链路。Qwen 规划可能需要 20–180 秒，
场景运动约 5 秒。任务失败后查看执行记录，点击重置恢复初始场景。

如提示容器名称已占用，说明已有演示容器；无需重复启动。只需启动 `sim-web` 并打开网页。

## 通信与完成条件

```text
浏览器 :8765 → 本机 RAI 子进程 → SafetyGate
          → HTTP 网关 :8766 → /embodied_agent/sim/action
          → ROS 仿真节点 → /embodied_agent/sim/status（指令编号、成功/失败）
                       → /embodied_agent/sim/observation（20+ Hz 场景状态）
          ← 网关状态订阅 ← 浏览器画面与任务验收
```

每条运动指令带 UUID 和 20 秒有效期，状态等待有超时限制。成功反馈在轨迹执行完毕后
发出。模型输出的 `stop` 终止后续计划；用户停止还会取消同一任务尚未执行的指令。
任务最终仅在红色积木位置落入盒子区域且夹爪松开时显示成功。
这比原 mock runtime 的“发完全部动作就成功”多了一层独立位置验收。

只映射本机端口；无需云端模型、外部前端资源或额外仿真引擎。
关闭网页不会停止服务。`sim-web` 终端按 Ctrl+C 关闭控制台；
运行 `docker stop embodied-agent-sim` 停止并自动移除临时仿真容器。

## 当前边界

- 固定桌面场景：`red_block` 与 `box`，只验收积木入盒任务。
- 机械臂采用两连杆逆运动学与预设笛卡尔路径；夹爪抓住物体后，物体位置跟随夹爪。
- 没有接触动力学、摩擦、重力或碰撞检测。`inside_box` 是几何位置判断。
- `verify` 检查仿真状态；尚未接入视觉识别、LeRobot 策略或真实机器人。
- 仿真 Topic 带独立 `/sim/` 前缀，原有 `make ros-demo` 仍是单独的消息接受测试。

## 任务交互与暂停

控制台显示已完成步骤数、当前步骤、已用时间和终态。任务提交期间及运行期间禁止重复启动和重置；空指令不能启动。失败时保留原始错误，并给出连接、模型配置、定位/抓取或超时等分类及恢复建议。

“完成当前动作后暂停”是步骤边界暂停，不会冻结正在进行的物理动作。规划阶段请求暂停时，计划生成后在第一步之前等待；执行阶段请求时，当前动作完成后在下一步之前等待。页面先显示“暂停已请求”，进入等待后显示“已暂停”；继续会执行剩余步骤。学习抓放被合并为一个动作，无法在该动作内部暂停续跑；需要立即中断时使用停止。最后一步完成后会直接验收，不再等待暂停。

新增 JSON POST 接口 `/api/pause` 和 `/api/resume`，仍遵循本地 Origin 校验。停止可以唤醒暂停任务，且不会继续发送后续动作。重置必须等待任务线程结束。进度是步骤计数，不是预计完成百分比；用时包含规划与暂停时间。

断连时禁止启动、重置和暂停/继续，并标记画面可能已过期，停止入口保留。`/api/state` 在执行服务断连时仍返回任务状态：`world=null`、`connection_error` 为错误详情，HTTP 200 仅表示控制台可达，不代表 ROS 在线。客户端应同时检查这两个字段。恢复连接后重新获取真实状态。

验证：10 项仿真/控制台测试通过，覆盖暂停边界、继续、暂停中停止、重复启动/重置保护和失败解释；JavaScript 语法及 Ruff 检查通过。浏览器检查了无 ROS 服务时的断连提示与禁用状态。本轮没有启动 Docker/ROS/MuJoCo 全链路，暂停逻辑通过模拟 bridge 的线程测试验证；未改动物理执行器或训练策略。

### 规划停止响应修复（2026-10-17）

已修复上一节的 RAI 工作进程等待问题：控制台把本次任务的取消事件交给规划器，每 100 ms 检查一次。取消或超时后先终止本地 RAI 工作进程，若 0.5 秒内未退出则强制结束，随后回收进程并关闭通信管道。已取消的任务不会启动工作进程；取消和结果同时到达时优先处理取消。共享 Ollama 服务不受此操作影响。

这消除了等待完整规划返回/180 秒规划超时的必要，但不保证 Ollama 服务内部立即停止底层推理，也不改变 ROS 停止请求在网络故障时的等待时间。其他不传取消事件的规划调用保持原有接口和执行方式。

7 项新增测试使用真实 Python 子进程验证正常 JSON、错误/无效输出、提前取消、运行中取消、忽略 TERM 后强制结束、超时以及控制台停止后释放忙碌状态。取消测试以 2 秒为测试上限，检查工作进程退出和管道关闭；控制台测试的 bridge 为替身，验证零运动下发及可重置。全部 33 项核心测试、Ruff 和 diff 检查通过。本次没有重跑 Qwen/ROS/MuJoCo 全链路，前一轮记录仍仅代表修复前的集成运行。

### 终态进度一致性修复（2026-10-18）

上一轮真实取消/重启报告中的新任务虽然成功，但 Qwen 末尾 `stop` 被单独分支处理，未增加完成计数，导致显示 3/4。现在计划内的停止与其他动作共用执行确认、取消检查、完成计数和事件记录流程；停止得到确认后才计入完成步数，因此该类完整学习计划应显示 4/4，预设轨迹同类计划显示 5/5。

用户停止和规划器计划内停止仍然区分：用户取消不被计为完成计划动作；停止接口失败也不增加计数。即使步骤全部执行，最终位置验收失败仍显示任务失败，满进度不等于任务成功。历史机器报告保持原样，不重写此前的 3/4 记录。

新增 4 项回归测试（含两种执行模式），全部 37 项核心测试通过；既有 `check_simulation.py` 现会同时断言规则与 Qwen 成功任务的完成步数等于计划长度，防止后续联调漏掉这类问题。Ruff 和 diff 检查通过。本轮使用 bridge 替身复现并验证控制台状态，未重跑 Qwen/ROS/MuJoCo 全链路。

### 停止确认与断连反馈（2026-10-18）

用户取消任务和执行端确认停止现分别记录。新增 `task.stop_confirmation`：`not_requested`、`pending`、`confirmed`、`unconfirmed`，另以 `stop_error` 保留停止失败详情。用户取消后 `phase=stopped` 表示控制台不会再执行该任务；只有 `stop_confirmation=confirmed` 才表示执行端已回复停止成功，不能仅凭 stopped 推断机器人状态。

停止请求失败时页面显示“任务已取消，但执行端停止尚未确认”，并显示原因和重试建议。即使任务已不忙，停止未确认时仍可再次点击停止；确认成功后清除错误。任务本身失败时保留原失败原因，同时独立展示停止清理失败，不用清理错误覆盖原故障。

停止回复绑定任务编号：旧任务迟到回复不能修改新任务或重置后的状态；同一任务一旦收到停止确认，较晚返回的重复请求失败不会抹掉该确认。本字段用于用户停止和失败后的清理，计划内停止仍由步骤确认/完成记录表示。

新增 5 项测试覆盖断连重试、成功后迟到失败、旧任务迟到回复、原失败保留及取消但停止未确认。全部 42 项核心测试、Ruff、JavaScript 语法与 diff 检查通过。本轮通过模拟执行服务失败验证状态逻辑，未进行浏览器交互或 ROS 网络故障注入测试。

### 受控连接故障与停止重试补验（2026-10-18）

已通过真实控制台 HTTP → 本地故障代理 → ROS/MuJoCo RGB-D 执行链路补验停止确认。故障代理只让新的请求返回 HTTP 503，已转发的抓取请求继续运行；期间未重启或重置仿真后端。这是应用层不可用故障注入，不等同于 TCP 黑洞或真实断网。

实际结果：抓取期间注入故障后，停止请求返回错误；控制台任务进入 stopped，`stop_confirmation=unconfirmed`，同时 `world=null`、连接错误和停止错误均保留。直接观测后端发现已下发的抓取仍完成且保持夹持，说明失败的停止请求不能被当作物理停止确认。

恢复代理转发后，对同一 run_id 重试停止成功，状态变为 confirmed、清除停止错误，后端没有活动动作，仿真时间未回退。随后重置并启动新任务，4/4 步完成入盒，新任务的停止状态为 not_requested。

3 项实际链路检查及 42 项核心测试全部通过，Ruff 与 diff 检查通过。没有修改生产逻辑；本轮通过真实 HTTP 接口验证提供给页面的状态，未做浏览器视觉检查、TCP 超时或网络抖动测试。

复现：先启动空闲的 RGB-D MuJoCo 服务，保持 8765、8767 端口空闲，再运行 `make stop-disconnect-check`。脚本创建自己的临时控制台和本地代理，结束时关闭；已有控制台或活动仿真动作会被拒绝。运行会重置测试场景，不应与人工操作同时进行。报告默认位于 `outputs/stop-disconnect-v1.json`，存在时拒绝覆盖，可用 `scripts/check_stop_disconnect.py --report <新路径>` 指定新报告。完整状态和源码哈希见[机器报告](evaluations/stop-disconnect-v1.json)。

### 无响应连接的超时与恢复（2026-10-18）

状态查询和停止请求原先共享 25 秒 socket 超时，可能让页面长时间等不到停止反馈。现在这两类请求使用 3 秒超时；普通动作/重置仍为 25 秒，学习抓放仍为 95 秒，不压缩动作执行预算。底层 bridge 超时直接报错，不自动重发命令；控制台既有的异常清理停止仍保留。

真实 ROS/MuJoCo 联调通过本地代理接受 TCP 连接后不返回任何响应头或内容，已转发的抓取继续运行。实测停止请求约 3.002 秒返回错误，状态查询约 3.003 秒返回连接错误和保留的任务状态。停止保持 unconfirmed；恢复代理后同一任务重试得到 confirmed，再重置的新任务成功入盒。4 项联调检查通过，后端在故障和恢复之间未重启。

这是无数据返回时的 socket 超时，不是严格的请求总墙钟截止时间；未覆盖持续缓慢发送字节、DNS 卡住或操作系统级丢包。本轮没有浏览器交互验证。新增 2 项超时预算/不自动重发测试，全部 44 项核心测试、Ruff、diff 检查通过。

复现使用 `make stop-timeout-check`，要求空闲的 RGB-D MuJoCo 服务、空闲的 8765/8767 端口；临时控制台和故障代理由脚本创建并回收。报告默认 `outputs/stop-timeout-v1.json` 已存在时拒绝覆盖。可用 `scripts/check_stop_disconnect.py --fault timeout --report <新路径>` 指定新报告。默认 `--fault http503` 保留上一轮的立即失败模式。[机器报告](evaluations/stop-timeout-v1.json)保存实测时延、故障和恢复状态及源码哈希。

### 最近任务记录与导出（2026-10-19）

### 本地持久任务记录（2026-10-19）

默认控制台现在将最近 20 个已结束任务保存到 `outputs/task-history.json`，重启后自动加载。此前“重启清空”的会话内限制已取消；重置场景仍不删除历史。启动只恢复历史，不恢复忙碌状态、不重放任务。未结束任务不进入历史，进程异常退出时的在途任务尚不支持恢复。

文件带版本号，读取时校验结束状态、编号唯一性、时间戳、事件及错误字段，限制最多 20 条/2 MB。保存采用同目录临时文件、flush/fsync 后原子替换；相同内容不重复写盘。该方案适用于单个控制台进程，不提供多进程合并或跨机器同步，也不保证断电时目录项持久性。

文件损坏、未知版本或读取失败时保留原文件，禁用本次进程对该文件的覆盖，新增记录仍可在内存查看/导出。请先备份并修复文件，再重启控制台。普通写入失败时保留原文件及内存记录，后续保存会重试；已结束当前任务的刷新也会触发保存检查。保存告警通过 `storage_warning` 返回，在页面与导出 JSON 中保留；`scope=local` 表示配置了本地存储，不代表当前保存一定成功，应同时查看警告。

文件保存在已忽略的 outputs 目录，不进入 Git；包含任务指令与错误详情。导出、筛选、搜索仍针对加载/保存的最近 20 条记录。测试中的 `SimulationApp()` 不传存储路径时继续使用会话内模式，避免写入真实历史。

### 任务复盘概览与汇总导出（2026-10-20）

最近任务新增复盘概览，随结果筛选、关键词搜索和历史刷新更新。展示完成/失败/取消数量、完成比例、停止未确认/等待确认数量、耗时中位数与最长耗时，以及按已有失败标题归类的次数。归类只包含 failed 记录，不把取消或停止清理错误当作新的失败任务；缺少标题时归入“未分类失败”。标题作为纯文本展示，按次数降序、同次数按标题确定排序，不推断底层根因。

统计只覆盖当前匹配的本地最多 20 条记录，不是完整运行日志或独立策略评测。完成比例 = success / 全部匹配记录，分母包含失败和取消。停止状态独立计数，不改变任务结果。耗时 = finished_at - started_at，包含规划、执行、暂停及结束前清理等待；只纳入有限数值且非负的时间差，零耗时有效，并显示有效及排除条数。没有记录时完成比例为 null，没有有效时间时中位数/最长耗时为 null，页面显示“暂无统计/暂无数据”。

批量及单条 JSON 导出新增 summary，与各自导出的 tasks 一致；completion_ratio 为 0–1 比例，duration_seconds 使用秒，failure_groups 保留完整分类计数。原有 selection、snapshot_stale 和 storage_warning 继续保留。刷新失败时概览与记录一起保留旧快照及提示，恢复成功后一起更新；不会把旧统计与新记录混用。

### 完成日期筛选与清除筛选（2026-10-20）

最近任务增加完成日期起止输入，可与结果和关键词取交集；单边日期也可使用。“清除筛选”一次恢复全部结果、空关键词及空日期，不删除记录或改变当前任务。日期按浏览器本地时区解释，以 finished_at 作为筛选依据：开始日零点包含、结束日的下一天零点不包含，因此包含结束日全天。按日历递增计算边界，兼容夏令时的 23/25 小时日期，不假设每天固定 86400 秒。

无效日期或开始晚于结束时提示错误，清空匹配列表/概览并禁用批量导出；清除或修正日期后恢复。设置日期边界后，完成时间缺失或不是有限数值的记录不匹配；不设日期时保持原有行为。仍只检索本地保留的最近 20 条记录，不代表该日期区间的完整运行历史。

批量导出的 selection.time_range 保留 start_date/end_date 和以 Unix 秒表示的 from_inclusive/until_exclusive，未指定的边界为 null，便于跨时区复核选择范围。列表、复盘概览和导出使用相同选择结果。单条导出按任务编号选择，time_range 为 null，不宣称导出了整个日期范围。

新增 6 项前端测试，包括完整末日、开区间、非法/闰年日期、独立纽约时区进程的夏令时边界、页面/统计/导出一致以及清除筛选。全部 21 项前端测试通过，JavaScript 语法及 diff 检查通过。本轮仅修改前端及文档，未重跑 Python、浏览器视觉或 ROS/MuJoCo 测试。
