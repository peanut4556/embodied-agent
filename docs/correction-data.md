# 模型偏离后的纠正示范与抓取质量复查

本阶段已完成实际模型执行后的专家接手采集、来源标注、精确回放与带损失屏蔽的训练
读取入口。**尚未用这些新数据重训模型**，控制台继续使用原反馈控制器。

另一个重要结果是对上一轮指标的澄清：记忆模型的 1/3 是“最终入盒”，不是完整抓放。
在同一组已查看场景上增加过程证据后，记忆模型合格抓放为 0/3，原反馈控制器为 3/3。
这是事后质量复查，不是新的独立测试；原始入盒结果保留，不回写历史报告。

## 什么算合格抓放

新增 `GraspQuality` 仅作为评测和数据整理工具，不给模型提供物体真值。25 Hz 下要求：

- 至少连续 3 帧双指夹持；
- 夹持时物体中心高于 0.15 m，持续至少 3 帧；
- 此后物体在盒上方、夹爪主动张开，并观察到接触释放；
- 物体最终稳定在盒内且已松开，持续至少一秒。

中途非主动释放会使该次提升证据失效，重新抓取后可以建立新的证据。
仅进入盒内、短暂接触、未抬起或闭合夹爪时掉落，不能通过合格抓放检查。
这些是当前模拟场景中明确、可复验的证据阈值，不评价全部动作平滑性或接触力质量。

质量复查中，记忆模型在 x=0.306 的那次入盒没有稳定夹持、持续提升或主动释放证据，
最大物体中心高度约 0.118 m，被标为 `goal_without_verified_pick_place`。
不据此进一步断言具体是推入、碰入还是其他接触过程。
原反馈控制器在两个正常场景和一个滑落场景均具有完整抓放证据，停止命令检查也保留。
新评测报告同时保留原来的 `success` 与新增的 `quality.verified_pick_place`，避免混用。

## 纠正示范如何产生

冻结的学习模型为 `outputs/models/memory-bc-v2/epoch-2000`。每段独立初始化 MuJoCo，
先让它按真实观测执行 2 或 4 秒，再从当时真实关节、速度、控制目标及物体状态接手。
接手不会重置积木位置；记录完整初始状态和接手瞬间状态，回放时逐项核对。

专家先从当前关节姿态退回观察姿态，保持已有接触抓持或张开空夹爪，然后使用 RGB-D
定位和 IK 轨迹完成抓取、运输及释放。若已经夹持则尝试放置。专家动作按与数据相同的
25 Hz 时钟执行，每个目标在整帧内保持，采用与原控制器相同的目标变化限制。
视觉无法可靠定位时停止，不用仿真真值坐标替代定位结果。

这是一种 **模型前缀＋专家接手的纠正演示**，并非给每个模型访问状态都查询专家标签的
完整 DAgger 训练循环。还没有自动检测何时需要接手；接手时刻由冻结开发配置指定。
专家使用 RGB-D 和 IK 生成标签，而未来学习策略的输入仍限制为 RGB、关节和夹持状态。

采样在动作计算前读取观测，再保存该帧实际执行动作；积分随后进行。专家和学习模型的
动作来源按帧区分。用户停止锁定首次停止目标，保留夹指目标，后续帧不追随运动中的
关节位置不断更新停止命令。最终版本为 `corrections-v2`；初次 `corrections-v1` 中
发现重复停止会更新目标的问题，已修复并完整重新采集，不作为最终批次使用。

## 字段及读取约束

沿用 LeRobot v3 的 RGB、关节位置、速度、夹持状态、标准 float32 `action` 和精确
float64 `replay.action`，后者只服务于物理回放。新增字段为：

| 字段 | 含义 |
| --- | --- |
| `controller.source` | 0 学习模型、1 专家、2 终态静置、3 停止 |
| `supervision.valid` | 只有整个 episode 合格且本帧为专家动作时才为真 |
| `next.success` | 最后一帧的合格抓放结果；失败为假 |
| `next.done` | 最后一帧的采集结束标记；失败过程也会正常结束 |

`training_sequences(root, group)` 是按 episode 读取的迭代器，仅接受 train/validation。
它返回独立的 `inputs`、`targets` 和 `loss_mask`，以及诊断用的 episode 编号：

- 成功 episode 的学习模型前缀保留为历史观测，但对应 `targets` 全部置零、mask 为假。
- 专家纠正动作才作为非零训练目标，必须用 `loss_mask` 计算损失，不能把零值当作动作。
- 终态静置同样屏蔽，失败与停止 episode 不进入这个成功模仿读取入口。
- 阶段来源、mask、未来结果、精确回放动作和物体真值不进入模型观测。
- 读取前检查源文件哈希；修改数据后必须重新回放验证。没有并发写入锁，读取期间应
  保持源数据不变。完整图像序列仍有内存开销，训练器应逐段提取特征，不积存所有图像。

原有固定轨迹训练器新增明确拒绝纠正数据；其他无损失屏蔽的训练入口也不能直接读取
这种新数据类型。后续应新增专门的带 mask 训练路径，保留学习前缀对隐状态的作用。

## 运行和验证

沿用 [数据集依赖](datasets.md)，采集需要本地 MuJoCo 图形连接，回放不需要渲染。

```bash
make correction-record
make correction-check
make correction-test
```

默认批次为 `outputs/datasets/corrections-v2`。已有输出拒绝覆盖；重采集可指定
`CORRECTION_DATASET=outputs/datasets/corrections-new`，学习权重通过 `CORRECTION_MODEL`
指定。所有过程在独立仿真世界内执行，不接管 ROS 任务，不上传数据。

验证器逐帧读取 LeRobot 数据，用 float64 保存动作重放，检查状态、速度、夹持、时间戳、
来源转换、监督 mask、停止锁定、接手状态、终止标签和抓放质量证据。七段均匹配，
机械臂最大读回误差约 1.2e-7 rad。图像检查维度和有效数值，不声称完成逐像素渲染一致性验证。

发现接手状态损坏会撤销 `selection.json` 的有效标记；恢复原数据后重新回放才能恢复。
测试还覆盖学习前缀不能成为动作目标、失败帧不被训练读取、场景分组不泄漏、意外落盒
不能冒充抓放，以及重复停止目标锁定。完整报告见
[correction-v2.json](evaluations/correction-v2.json)。

本轮 51 项代码测试通过，包括真实数据接手状态损坏与恢复验证；四段合格 episode
也已通过实际训练读取检查，训练与验证各 622 个有效目标，学习前缀的目标均被屏蔽。

下一步应扩大晚接手、遮挡和模型错误接触后的可恢复样本，再进行带监督 mask 的模型
微调；开发选模要明确优先采用合格抓放指标。当前记忆模型选模入口仍保留旧实验的
“最终入盒”排序规则，新质量字段是额外诊断，尚未据此重新训练或选模。

后续阶段已完成扩充和实际微调：有效训练纠正动作增至 2,488 帧，但三个候选的开发合格抓放仍为 0/3。见 [纠正微调实验](correction-finetune.md)。上述“尚未重训”仅描述本文件对应的旧阶段。
