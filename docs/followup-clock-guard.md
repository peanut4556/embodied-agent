# 后续监测等待期间的时钟保护

2026-11-02。修复 ProcessPostConfirmation 在等待采集结果时未持续检查时钟映射的问题。本轮不改变区域、告警时长或映射误差阈值。

## 问题与修复

此前收到新帧时会通过 ExposureClockMap 校验时钟；但请求仍在等待时，仅计算主机时间与上次有效曝光之间的年龄。如果主机时钟暂停或回退，年龄可能一直很小，即使任务时间已明显前进，旧的 inside_region 状态仍可能保留。任务时间非法时也只是抛出异常，旧观测状态没有立即失效。

现在对每次非终态 step，在 IPC 轮询之前和之后分别读取并校验主机时间：

- 主机时间须有限，不早于映射原点，且不能相对上次读数回退。
- 用原有仿射映射计算对应任务时间，其与本次 task_now 的差不能超过 max_error（默认 20 ms）。不要求两个读数完全相等。
- 时钟读取异常、无效值、回退或超差使监测进入 invalidated / invalid_followup_clock，当前观测状态转为 unknown，清空可复用的最近采集时间，并记录错误。
- 轮询前失败不执行 IPC 或新请求；轮询后失败则不使用刚取得的帧，也不继续预取。
- 非递增、过早或非有限任务时间先使监测进入 invalidated / invalid_task_clock，再按既有接口抛出 ValueError。调用方即使捕获异常，也不能继续读到有效的旧区域状态。

例如最后一次接收为 task=1.125 s、host=17.125 s，此后 task 到 1.25 s 而 host 停留在 17.125 s：旧的年龄计算可能仍保留区域内状态，新逻辑会因 125 ms 映射偏差立即终止监测。

停止、已有终态、会话归属变化和到期检查仍先执行。停止或到期不读取已经损坏的时钟源。有效映射范围内的微小误差，以及没有新帧的普通轮询，不会中断区域外证据连续性。

## 生命周期与限制

时钟异常不自动校准或重启，也不改写原来的 confirmed_in_tray 结果。旧监测终态锁定；若需要新窗口，应由调用方重新建立可信映射和合适的会话。采集进程仍需显式 close 或退出上下文回收，cleanup_required 在实际回收成功前保持 True。

这是单一拥有者、由调用方调度的实验监测入口。如果调用方完全停止调用 step，不会有后台时钟检查。轮询期间调度延迟大于映射容差也可能使监测失效，这是当前固定容差的保守行为，不构成硬实时保证。
