# 带独立验证的预算恢复闭环

日期：2026-11-24。

## 实现与调用

新增 ActionBudget.validated_recalibrated：先由校准批次计算冻结候选（最大耗时加原裕量），再用另一验证批次检查，所有验证耗时必须不超过候选预算。两批都必须满足原 minimum_samples，验证样本不参与抬高或降低预算。任一失败不返回候选，也不更改旧实例、暂停状态、版本或校准历史。原 recalibrated 仍可用于调用方已在外部完成验证的显式恢复，默认运行行为不变。

```python
replacement = budget.validated_recalibrated(
    "verify", calibration_samples,
    batch_id="verify-cal-002",
    validation_samples=holdout_samples,
    validation_batch_id="verify-val-002",
)
# 只有上面成功返回，才显式替换在用对象。
budget = replacement
```

批次名必须非空、无首尾空白且最多 128 字符，校准与验证批次必须不同。当前版本链内，已用于验证的批次也不能再次作为校准批次，反向同样禁止。旧对象继续保留原暂停状态，其他动作状态不变。恢复记录新增验证批次、数量、最大值和 SHA-256，返回历史仍是深复制。运行测量 record 同时加固：非有限/负数耗时及非布尔确认值拒绝，避免 NaN 静默绕过越界判断；零耗时允许用于虚拟时钟测试。

这是调用方负责组织的独立数据接口，不是数据来源认证。不同批次名不证明数据独立，摘要不防止更名复用；API 没有采集设备、持久化批次注册表或自动维修。未知真实耗时的校准/验证采集必须由外部受控流程完成，不应靠反复重试正式任务搜集恢复样本。

## 顺序实验设计

比较一直暂停、重新校准直接恢复、独立验证通过后恢复。三种环境：十次变慢后恢复；一直变慢；恢复后第 26 次再次变慢。每场景每策略 40 个核验任务，共 360 次。初始校准种子 81000..81039、重新校准 82000..82039、验证 83000..83039、正式任务 84000..84039，四组不重叠。每组 40 个样本，正常耗时 5–12 ms，变慢 30–50 ms，剩余时间 20–60 ms。

在第 11 个任务前安排固定维护机会，不根据未来任务结果选择恢复时刻。重新校准模拟采到较快的样本；持续变慢场景的验证仍采到慢样本，故验证可识别这次不具代表性的校准。另两个场景的验证采到正常样本。这是人为构造的校准失配反例，不是自然发生频率估计。所有实际执行均通过 AgentRuntime，真实未来耗时不传入预算对象。

| 策略 | 完成/120 | 可行任务误拒绝/80 | 已派发未确认 |
|---|---:|---:|---:|
| 一直暂停 | 0 | 80 | 3 |
| 直接恢复 | 45 | 35 | 5 |
| 独立验证后恢复 | 45 | 35 | 4 |

独立验证阻止一次仍然变慢时的恢复，未损失本批直接恢复能完成的任务；相对一直暂停恢复了 45 次完成。第二次漂移仍造成新的首次失败，随后重新隔离。验证并不保证未来，结果也不是对抓取/放置或实机的泛化声明。

完整维护批次、逐次任务、状态和摘要在 [冻结记录](evaluations/budget-recovery-v1.json)。本报告没有新增源码哈希字段，代码与记录在同一 Git 提交中保存。


独占创建输出，不能覆盖已有记录。新增五项测试覆盖：候选不拟合验证数据、验证失败原子性、样本不足/非法值、跨角色批次复用、运行测量非法值、冻结顺序实验、持续慢时不恢复、再次漂移后停止派发。相关回归总计 95 项通过。此前实验默认行为与历史记录保持一致。

## 使用边界

保持默认策略，只有明确使用 quarantine 并选择此恢复入口才具备这组恢复语义。无自动等待后解封、无自动重新训练。验证失败后应保留暂停，重新检查采集条件；若要再试，需要调用方提供具有代表性的新校准和验证批次。当前没有实机数据，也没有对尾部覆盖概率、并发切换或跨进程故障恢复作保证。
