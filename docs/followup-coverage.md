# 后续监测的观测覆盖诊断

2026-11-02。为 ProcessPostConfirmation.result 增加独立 coverage 字段，量化无告警背后的观测缺口。区域外告警、时钟校验、停止及资源回收行为保持不变。

## 计算口径

仅累计连续有效曝光之间、间隔不超过 250 ms 的区间；相邻区间合并，不重复计时。单个曝光点只计样本，不贡献时长，也不向前或向后填充到任务窗口边界。

明确缺失、被拒绝的采集结果和等待期间证据过期都会切断区间。有效样本必须晚于监测起点、早于期限并严格递增。普通 pending 轮询不增加样本数，旧证据过期只记录一次 expired，不按轮询频率重复累加。

| 字段 | 含义 |
| --- | --- |
| planned_seconds | 原计划监测窗口时长 |
| covered_seconds / coverage_fraction | 符合上述规则的曝光区间总长度及占原计划时长比例 |
| uncovered_seconds | 计划窗口中未被这些区间覆盖的长度 |
| longest_uncovered_seconds | 区间补集中的最长一段，含起始和结束缺口 |
| counts | valid、missing、rejected、expired 次数；expired 是过期事件，不是相机帧数 |
| first_valid_exposure / last_valid_exposure | 首末有效曝光时间 |
| window_completed | 是否正常达到监测期限 |
| assessment | 无有效观测、窗口未完成、存在观测缺口或整个窗口被区间覆盖 |

即使提前停止、时钟失效或进程故障，分母仍是原计划窗口，不会用较短的实际运行时间抬高覆盖比例。监测仍进行中时，未来尚未观察的区间也暂时计为未覆盖。`assessment` 是描述性类别，没有设定“充分”或“安全”的百分比阈值。按当前要求曝光必须晚于起点，正常结果通常保留起始缺口，不应追求人为填充到 100%。

指标对区域内和区域外的有效曝光同等计数；它不代表区域内持续时间，更不证明采样之间的物体状态。没有有效观测的窗口即使 completed，覆盖率仍为 0。已有历史告警可与较低覆盖率或窗口未完成并存。

## 结果

[带覆盖诊断的 108 场景报告](evaluations/followup-coverage-v1.json) 中，原先状态与告警时刻检查仍为 0 项不一致。以持续区域外、125 ms 请求完成延迟、2 秒完整窗口为例：

| 掉帧 | 有效帧 / 缺失帧 | 覆盖时长 | 覆盖比例 | 最长未覆盖区间 |
| --- | ---: | ---: | ---: | ---: |
| 无 | 15 / 0 | 1.75 s | 87.5% | 0.1875 s |
| 每第三帧缺失 | 10 / 5 | 0.625 s | 31.25% | 0.3125 s |
| 全部缺失 | 0 / 15 | 0 s | 0% | 2 s |

这使调用方能够将“未告警且没有观测”“未告警且观测有缺口”“窗口提前结束”分别解释，而不是把未告警等同于持续区域内。
