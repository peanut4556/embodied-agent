# 采集调用方退出后的无编号恢复

2026-11-15。本轮把持久化索引发现能力接入真实时钟采集后的进程退出实验。恢复程序只知道源数据库和检查点仓库路径，不接收 receipt_id，也不依赖原进程的回调结果。

## 故障边界

父进程初始化空账本和检查点基线，随后启动独立调用方进程。调用方内部启动预约式双视角采集进程，完成两阶段确认，由 EvidenceInbox 将实际产生的 receipt 送入账本。

- 提交前退出：索引事务已提交；在证据事务 COMMIT 执行前，通过 SQLite trace 回调执行 os._exit(91)。
- 提交后退出：ledger.record 返回后、消费者回调返回前执行 os._exit(92)。

退出前先显式回收采集工作进程，并保存不含证据编号的状态标记。这个安排避免留下测试子进程；它没有验证“采集资源尚未回收时强杀调用方”的生命周期问题。

父进程等待退出后仅打开源库让 SQLite 处理热日志，不重交 receipt，不重新登记检查点。随后通过 discover_from_store 自行发现持久化索引，再运行严格 preview_publication。索引是在原进程中按真实 receipt 生成的，不是恢复程序预先知道编号后查询。

## 结果

```sh
make capture-owner-exit-check CAPTURE_OWNER_EXIT_OUTPUT=outputs/evaluations/capture-owner-exit-new
```

首轮 4/4 符合预期：

| 每种两次 | 调用方退出码 | 从磁盘自行发现 | 严格预览 |
| --- | --- | --- | --- |
| 证据 COMMIT 前退出 | 91 | 一条索引，not_found | source_rejected |
| 证据 COMMIT 后退出 | 92 | 一条索引，recorded | proposed |

四次都进入确认成功后的消费路径；采集工作进程全部在注入退出前回收。恢复程序未重放消费，也没有自动发布提案。查询到未落账只描述本地证据事务，不是任何外部副作用不存在的证明。

[保存的实验记录](evaluations/capture-owner-exit-v1.json)包含退出码、发现结果、预览状态、资源标记、源码及数据库/仓库哈希。69 项相关证据链测试回归通过，Ruff 检查通过。脚本保留全部案例结果，未达目标场景时返回非零；不自动重采以挑选成功结果。

## 进展与限制

本轮把“调用方内存丢失后仍能找到恢复线索”从手工审计输入推进到真实进程、真实时钟采集产生的证据，覆盖提交前后两个明确故障点。读取器依旧是合成双视角，未接入真实相机或机器人；没有断电、任意指令点崩溃、长期成功率或实时性能保证。

恢复依赖数据库路径、持久化索引及独立检查点仍可获得。索引提交之前退出没有该条索引可发现，源库与仓库一起回退仍需更外部的见证。本轮不覆盖这些原有限制。父进程超时会终止本次测试独立进程组，超时不会被记为成功回收场景。
